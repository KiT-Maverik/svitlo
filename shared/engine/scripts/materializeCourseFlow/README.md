# Materialize a reviewed Course plan (Stage 5)

This Engine utility consumes **one temporary Course YAML** under content/<book>/data/courses/<bucket>/<course-uuid>/course.yaml. It creates Course-owned TypeScript/Markdown drafts and any required Lesson methodology-only YAML handoffs. It never writes intermediate config.yaml and never opens Lesson PRs. The resulting Course TS/Markdown files are the durable source of truth.

## Usage

Run the maintained script shared/engine/scripts/materializeCourseFlow/materialize-course-flow.mjs with:

- --package content/<book> --course <uuid> --write
- --package content/<book> --course <uuid> --check
- --package content/<book> --course <uuid> --finalize

## Inputs and outputs

The single Course YAML has independently reviewed pedagogy, audience and Skills, Modules, Chapters, reuse references to existing Lessons, and full inline methodologies for new Lessons. Episode nodes, when authored, include independently specified Sections and content. Source language must belong to intended languages. Reviewer approval is tracked separately in the parent Course PR: this CLI cannot grant it.

Output files include `index.ts`, `methodology.md`, `constants.ts`, `review.ts` (unapproved review skeleton), `modules/*.ts`, `chapters/*.ts` and `episodes/*.ts` with their barrel files. The root index holds Course content ordering. Episodes reuse the nested Course Builder renderer for Sections/blocks. The Course/Module/Chapter source uses `define*<Slug, Items, CourseLanguages>`; the Episode root uses its real `defineEpisode<Slug, Languages, Sections>` argument order. Course references the family barrels; Modules reference Chapters without importing a parent barrel. Property shorthand and grouped package/alias/relative imports keep drafts small.

For each new Lesson with inline methodology and no ID, Stage 5 derives a stable UUID from the Course UUID and canonical placement path. It creates only content/<book>/data/lessons/<last-hex>/<uuid>/lesson.yaml, with a minimal Config identity/Skills/language/title/empty-Sections shell and the reviewed source-language production.methodology text. Optional quizRequired on the slot supplies initial Quiz intent; absent values are provisional authoring shells, not independent approval. No Lesson TS, Questions, Flashcards, assets, translations, review or PR is created. Later Lesson Production reuses this exact ID and YAML.

Existing matched Lessons retain their actual IDs and source ownership. Source modules refer to standalone Lessons using the textbook's `package.json#imports` mapping `#lessonsData/*` (PR #595). For an implemented Lesson, retain its verified exported name; otherwise, use the canonical Lesson UUID and the `config.slug` from the existing `lesson.yaml` or newly materialized Lesson shell, targeting the **future** `index.ts` and its `slug_Lesson` export. These imports intentionally remain unresolved until independent Lesson Production creates the modules. Do not use `UNRESOLVED_LESSON_N` or fabricate a Lesson configurator. The Course never owns or duplicates reusable Lesson implementations.

The generated `constants.ts` follows the Lesson Builder convention: an active `languages` tuple containing **only `documentLanguage`**, `CourseLanguages = typeof languages`, and a commented-out alternative declaration retaining the complete planned `supportedLanguages` tuple. Root Course `params.languages` uses the active tuple. An editor can activate the complete tuple only after genuine translations are authored; neither this CLI nor a type error is permission to copy/fabricate translations. No separate `courseId` or `sourceLanguage` constant is necessary.

**A successful Course materialization is not required to pass TypeScript typechecking.** Unimplemented future Lesson imports, locale gaps and not-yet-authored Scene/media dependencies are valid Draft-only TypeScript errors. The CLI checks deterministic output bytes and **TypeScript syntax**, not complete typechecking or Props publication. This is intentional and should not be worked around with fake resources or `as any`. Before production acceptance, the actual textbook production build, external review evidence and full locale/resource coverage are required.

`review.ts` is an empty, explicitly unapproved Course review register. Unlike the independently typed `LessonReview` template, Engine currently has **no `CourseReview` contract**. Therefore the builder cannot emit a typed Course stage/revision register or populate imaginary methodology/experience/translation approvals. Independent reviews remain in the Course parent PR until a typed Course review contract is approved and implemented.

## Safety and lifecycle

`--write` validates every target before modifying files, refuses symbolic-link paths and divergent edited content, and uses exclusive creation. Derivation is deterministic: reruns after partial output use the same IDs. `--check` is read-only and compares generated bytes and TypeScript **syntax only**. `--finalize` refuses to run without exact matching materialized outputs; afterward it deletes **only the temporary Course `course.yaml`**. The new independent Lesson YAMLs stay until their own Lesson workflow finalizes them. Commit and independently verify the generated files before finalizing; Git history preserves the reviewed Course plan.

The general courseBuilder remains an unrelated Config-shaped draft scaffolder for older workflows, not a second mandatory YAML step. This materializer never publishes Props, fabricates media/Quiz answers/translations, or starts Lesson Production.
