# Source-pinned Flashcard Bank translation references

This named, read-only adapter renders **the complete statically authored Flashcard bank**, not just the Lesson's selected `flashcardIds`, as a bounded Markdown reference for one requested `content/<book>/data/lessons/<bucket>/<uuid>/flashcards/index.ts` and language.

The canonical entrypoint is [generate-translation-review-artifacts.mjs](../../../../scripts/generateTranslationReviewArtifacts/generate-translation-review-artifacts.mjs), invoked via `--kind flashcards --package content/<book> --lesson <uuid> --locale <language>` or the authorized `/agent-artifacts generate flashcards content/<book> <uuid> <language>` command on the **existing Flashcards entity PR**. The adapter is not a publisher, translator, authoring tool or review-approval system.

It uses the current TypeScript AST **without executing authored TypeScript**. Supports the Flashcard Builder's `defineFlashcard`/`defineFlashcardSide`/nested `define*` literal structure, including source-language metadata spread, and requires the Builder-standard `// Lesson UUID: <uuid>; documentLanguage: <lang>` provenance header. It statically discovers **exactly one exported bank `items` registry** by shape, without relying on a particular variable name. Verified relative, named TypeScript imports may refer to Question Configurators and their ContentBlocks **inside the same Lesson UUID directory**; the evaluator traverses their literal `define*` Config without evaluating expressions or granting special handling to an obsolete Question folder layout. Every referenced file is linked at `manifest.sourceCommit`. Unknown/re-exported-outside-Lesson, dynamic, cyclic, ambiguous, missing or symlinked sources fail the requested review scope. Traverses all card sides and nested locale dictionaries, displays source/target text, IDs, flags and source links tied to `manifest.sourceCommit`, and produces `missing`/`reviewReady` diagnostics. Dynamic expressions, unrecognized imports, incomplete/mismatched identifiers, symlinks, oversized files and missing authoring context fail the requested scope instead of silently omitting cards or declaring review readiness. Other entity/locales are not touched.

The shared manifest records the requested kind/textbook/Lesson UUID/locale, exact source SHA, generated document, **all card fronts/backs/optional hints and authored flags**, count of card and localized fields, missing translations and failures. Unregistered declared cards also block review rather than being silently skipped. The original Playground `howLightMovesFlashcards` bank is exercised in integration tests, including all three imported Question fronts/backs; its standard source-language header was added without changing card identities, text, or language data. That bank's older _Question module directory layout_ is not thereby approved for the separate canonical Questions review adapter: follow the owning Questions workflow for any later migration. Reviewers independently verify the scoped document from the successful one-day Actions ZIP and perform any authorized fixes **on that same Flashcards PR branch**, followed by regenerated/reviewed evidence. Source language, meanings, reviewed vocabulary, locale completeness, typechecks, physical media and real publication are still independent requirements. A passing artifact generator is **not** linguistic approval.

Regression tests: `node --test shared/engine/scripts/generateFlashcardReviewArtifacts/generate-flashcard-review-artifacts.spec.mjs`.
