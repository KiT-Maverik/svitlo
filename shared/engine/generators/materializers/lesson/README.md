# Typed Lesson, Section and Quest source materializers

**Implemented:** concrete Lesson and Section/Quest source renderers under this directory, with the parent-owned trusted Lesson Stage 6.1 source transition. These are **Build-time source renderers**, not runtime Props serializers, YAML-to-TS builders or permission to publish an unfinished Lesson.

## ContentBlock production briefs

Ready-to-author blocks (`Text`, `Markdown`, `Code`, including Checkpoint questions) carry their finished learner-facing source in their Config/locale or code payload; they must not generate a separate `specification.md` or a redundant technical brief. Unresolved media retain one temporary, actionable implementation brief adjacent to their generated `index.ts`, not a detached sidecar. **Image briefs must provide a concrete image-generation prompt** describing the actual composition, subjects, layout, important visual relationships, and constraints, not just a generic purpose. Audio, Video and Subtitles preserve their real generation inputs (scripts/storyboards or text). Generic accessibility, offline, weak-device and readiness declarations are platform/workflow quality gates, not per-resource specification boilerplate; omit them from generated media briefs. Never remove the real publication blockers for missing assets, verified alt text, captions or QA.

## Ownership and stage boundaries

- **Optional Course seed:** Course Stage 5 emits a persisted UUID-addressed `draft.ts satisfies CourseWorkflowLessonSeed` with reviewed proposal and Course language context. Lesson Stage 1 is independent and may use this seed, operator brief or other material. Its authorized Methodologist completes `LessonWorkflowStage1` in the same file, preserving allocated identity. Course Stage 5 does not call the Lesson renderer, author Sections, mint bank IDs or open a Lesson PR.
- **Lesson Stages 1–2:** the same Lesson `draft.ts` evolves to `LessonWorkflowStage2` with typed plain `{config, production?}` nodes and `items/order` collections. Stage 3 independently reviews and Stages 4–5 audit/correct that exact source; Stage 2 remains the sole editorial materializer input; do not rewrite its type annotation at Stage 5.
- **Authorized Lesson Stage 6.1:** `materializeStage6.ts` composes the concrete Lesson, Section, Quest and nested Block renderers. It emits final `define*` modules, Lesson-root `constants.ts` (source-only active `languages` and `Languages` type), derived root `methodology.md` and materialization diagnostics. Reviewed Stage 2 production fields are never another editable source. Each reviewed Scene additionally emits six blocked but type-correct executable draft files under `scenes/<uuid-last-hex>/<uuid>/` in the owning textbook; its full reviewed specification is embedded as inert line comments inside the TSX, not duplicated as a Scene sidecar. Episode Stage 5 also generates six-file textbook-owned Scene drafts without a duplicate sidecar; independent Banks verify source-pinned Scene evidence rather than requiring a Lesson-created `specification.md`. Standalone consumers may still retain reviewed Scene sidecars when no owner-scoped draft is emitted. The same concrete Section/ContentBlock renderer serves a Lesson, Episode, and new Sections introduced by a Course Lesson placement. The caller supplies the output directory, language context and textbook-scoped Scene root; no synthetic Lesson is needed to render a single Section. All three paths retain the same nested Block and UUID-bucket Scene source layout. Only the owning parent chooses child placement/order. The materializer has no dependency on editorial reviews, PR prose, or Course provenance.
- **Source transaction:** the trusted [Lesson materialization](../../../../../scripts/ci/lessonMaterialization/README.md) owns the sole active Git writer (`scripts/ci/lessonMaterialization/lesson-typed-materialization.mjs`). It retains exact pinned input bytes in the pinned Git parent commit and blob while atomically consuming `draft.ts` and creating `index.ts`, approved Lesson-owned files and complete same-textbook six-file Scene draft directories in one non-force Git commit. Scene paths are UUID-bucket checked; incomplete Scenes remain unregistered. Validate authorization, source blob/HEAD and path/symlink/no-clobber preflight before publication of a plan; never execute untrusted PR TypeScript in a privileged job.
- **Later work:** Stage 6.2 resolves typed resources, 6.3 implements/registers/tests every Scene, 7/8 independently author full banks, and 9/10 translate/review all required locales. Source creation never grants these completions or publication.

## Concrete source kinds

The Lesson family owns ten separate implementations and adjacent tests: `lesson`, `contentSection`, `practiceSection`, `codingTaskSection`, `learningFlowSection`, `flashcardsSection`, `quizSection`, `questSection`, `questStage`, `questTask`. Each kind handles its real `define*` Config boundary; nested ContentBlocks are delegated to the distinct concrete Block materializers. Quest is a **Build-only** authoring Section without Lesson/Episode runtime registration. Do not make it publishable by disguising it as another Section.

Quest modules are emitted in their authored `sections/<slug>/` directory, but are excluded from the generated `defineLesson` Section map and order. The root retains a `TODO (BLOCKER)` and diagnostic until a separately authorized runtime contract exists. This keeps generated TypeScript valid against current Engine exports while preserving the reviewed Quest source.

An authored required Quiz/Flashcards Section must be **enabled and present** before complete Lesson emission. Missing/disabled required Sections fail closed; an existing but unfinished enabled Section may emit a visibly blocked non-publishable draft. `params.quizRequiredForCompletion` independently requires a real enabled Quiz. The full bank, Quiz selection and Flashcards selection are separate editorial decisions. A Course handoff must never manufacture a fake complete Lesson, Section, Card or Question to satisfy these requirements.

## Typed source and imported assessment references

Use stable UUIDs, camelCase slugs and real ordered collections; preserve only real source-language copy while listing planned untranslated locales as blockers.
The Lesson root emits one `TODO (BLOCKER)` in `constants.ts` before the **exact reviewed `production.languages.planned` tuple** (never a global 30-language roster); only `production.languages.document` is active. Lesson/Section modules import package-owned constants through `#lessonsData/<bucket>/<lesson-uuid>/constants`. Episode emission must preserve its own rooted import contract; it must not import a Lesson alias outside its package.

**#857 target:** Lesson Stage 2 authors verified literal Skill UUIDs, not imported `#skillsData/*` Configurator values or `.id` expressions. Trusted materialization separately resolves the actual textbook Skill dependencies and only generated `index.ts` contains executable imports. Unknown links remain publication blockers. The static Draft Reader cannot discover Skill exports; check actual deployment before applying this target.

Root `specification.md` is not emitted. Text, Markdown, Code and all nested Checkpoint text are fully authored source and must never emit per-block specification sidecars. Stage 2 Images require a concrete generation `production.prompt` (not generic descriptive boilerplate); temporary Image comments preserve that prompt, while media/Scene comments omit global accessibility, offline, device and readiness fields. Image, Video, Audio and Subtitles (including Carousel Image slides and Quest media) retain their complete reviewed implementation briefs as temporary multiline source comments **after** the generated `define*` call in the owning `index.ts`, with a `TODO (BLOCKER)` to remove the note only once the resource is implemented and verified. Those media materializers do not emit `specification.md`; Scene implementation guidance remains in executable Scene TSX drafts. A Flashcards Section additionally embeds its reviewed specification as an inert, removable source comment beside its implementation TODO; durable intent remains in Lesson methodology. Generated `methodology.md` retains the Methodologist's original prose and appends unique reviewed Lesson objective/depth/sequence/assessment evidence, four assessment decisions and named per-Section production notes. `sourceEvidence` never becomes a sidecar or an added methodology subsection. Quiz and Flashcard Bank requirements generate separate Stage 7/8 blockers only when the bank is required or the corresponding Section is pending. The Lesson renderer performs this consolidation before invoking child Section renderers and sets the ephemeral `methodologyIntegrated: true` in a Section's materializer options only when every reviewed metadata field was included or already retained verbatim. It never mutates the original Stage 2 source; unrepresentable notes remain blocked. Section `specification.md` retirement and recursive layout changes are separately owned by #832; Stage 6 nested import composition and publisher allowlist are owned by #833.

Constrain generated file paths and delegate nested import ownership. The authored declarative Stage 2 Lesson draft holds **verified literal Question/Flashcard UUIDs**, not value-imported Configurator `.id` expressions. Trusted analysis must check those IDs against real reviewed bank exports before generated completed Quiz/Flashcards Sections import actual Configurators. The historic `preserveAssessmentReferences.ts` behavior applies to the **pre-migration executable draft** and must not be represented as proof of declarative source compatibility. Unsupported expressions, missing bank dependencies and mismatched IDs fail closed; the exact reviewed source remains in Git history.

Source output with `TODO (BLOCKER)`, `TODO(asset)`, reserved IDs, missing Scenes or incomplete translations must remain blocked until independent acceptance. See [Lesson source layout](../../../../../studio/docs/architecture/lesson-generated-source-layout.md), [Lesson Flow](../../../../../studio/skills/lesson-workflow/create-lesson-flow.skill.md) and [typed architecture](../../../../../studio/docs/architecture/typed-production-materialization.md).

## Reproducible validation

From a clean dependency-installed checkout of the target HEAD:

```sh
node --test scripts/ci/lessonMaterialization/lesson-typed-materialization.spec.mjs
node --test scripts/ci/lessonMaterialization/lesson-typed-publish.spec.mjs
node --test scripts/ci/lessonMaterialization/lesson-typed-source.spec.mjs
npm run package:build --workspace @svitlo/engine
npm run code:check:types --workspace @svitlo/engine
npm test --workspace @svitlo/engine
```

Only an actual completed run against the current SHA establishes a passing check. A successful isolated renderer test does not prove the trusted default-branch GitHub command is deployed; the synthetic PR authorization/source-integrity smoke test is still a separate integration responsibility.
