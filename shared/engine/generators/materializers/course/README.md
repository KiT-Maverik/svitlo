# Typed Course family source materializers

**Contract clarification (#875):** Course-level Skill targets are genuine Config/Props fields and resolve to imported Skill `.id` references. Module/Chapter learning outcomes and prerequisites are **production-only methodology**, still verified against approved Skills and included in derived `methodology.md`; Config/Props reject these fields, and generated `index.ts` does not import Skills for them. Course-owned Lesson override fragments are checked against `CourseLessonSourcePatch` in inert editorial source and `CourseLessonBoundPatch` in generated trusted TypeScript. Existing Section and ContentBlock fragments use their concrete imported Configurator Build types; the real Lesson Build API remains the final validation boundary. Canonical child-export collisions cause explicit errors, never invented aliases.

**Implementation status:** the Course/Module/Chapter/Episode source renderers and typed Course Stage 5 orchestrator compose reviewed typed source. Their job is to emit reviewed, immutable **TypeScript authoring modules and derived methodology**, not runtime Course Props/JSON, editorial approval or a YAML conversion.

## Concrete kinds and responsibility

Nine independent kinds have their own implementations/tests: `course`, `module`, `chapter`, `episode`, `skill`, `skillGroup`, `skillDomain`, `educationStandard` and `assessmentMethod`. A parent determines the typed child map/order and where it belongs; each child's own `materialize.mjs` emits the appropriate `define*` module, export/import declarations, source-locale content, specifications and pending diagnostics. Episode delegates Sections to **the same concrete Section materializers** used under Lesson, without a separate Episode-only source generator.

**#857 target:** The author-edited Course Stage 1–3 source is a single inert default-exported typed object. The shared trusted Draft Reader parses exact pinned bytes without executing source; it validates the final `CourseWorkflowStage3` Zod schema before passing plain data to the trusted `materializeCourse`/Stage 5 orchestrator. The independently reviewed Course draft must not invoke `materializeCourse()` itself. All genuine Lesson dependency imports and Build overrides belong to separately trusted materializer code, not the authored `draft.ts`. See [Stage 5 orchestration](./STAGE5.md) and [Course runbook](../../../../../scripts/ci/courseMaterialization/README.md) for target details and current deployment caveats.

## Source layout

Course-owned source modules use a flat path per actual semantic owner: `<course-uuid>/index.ts`, `<course-uuid>/<module>/index.ts`, `<course-uuid>/<module>/<chapter>/index.ts`, with direct Lesson/Episode/Assessment child stubs or handoffs in `<owner>/<child-slug>/`. No structural `content/` path segment is emitted at any owner level. Course/Module/Chapter authored Config uses root `children` order and direct slug-named child placements; the retired `content.items/order` wrapper must not be emitted. All imports preserve the verified canonical export name. Materializers do not synthesize aliases, prefixes or collision suffixes. A real local identifier collision is a TypeScript/CI error for the Coding Agent to resolve in reviewed source, not a reason for the generator to rename the import. Keep previously allocated UUIDs stable when changing the physical layout; existing materialized trees are not silently rewritten.

## Lesson placements and safe source transition

- **New Lesson:** derive a deterministic immutable UUID from the Course root and full placement path, persist it, and emit **only** a new `CourseWorkflowLessonSeed` `draft.ts` under the Lesson's UUID directory. Preserve proposal methodology, Skill references, evidence and all four assessment booleans; derive seed language context from the Course root. It is not Lesson Stage 1. Do not emit `defineLesson`, Sections, Quiz/Flashcards placeholders, a bank or any imaginary content; the Course remains blocked until independent Lesson production.
- **Existing Lesson:** resolve the author-declared Lesson UUID and optional sparse `production.sourcePatch` from trusted, verified dependency context. Preserve imported Lesson identity, Skills and source SHA. Pure reuse emits a **direct import** in the immediate owning Course/Module/Chapter `index.ts`. A nonempty patch instead emits `<placement-slug>/index.ts` **inside that Course hierarchy** containing the original Lesson import and `placeLesson(source, patch)`; the parent imports the placement-local Configurator. The placement's exported constant uses its **placement slug**, never a generic `placedLesson` name; one temporary multiline `TODO (BLOCKER)` with the full reviewed override rationale and Course-owned Section/ContentBlock notes **after** the `placeLesson()` export in the same placement `index.ts` requires completing, testing and verifying the whole override before removing that single comment. Notes are never transferred into canonical Lesson or Course methodology; the shared Section renderer omits only the misleading transfer reminder in this placement context, while independent resource/Scene/bank and Section-implementation blockers remain. The original standalone Lesson slug and UUID are unchanged. Existing Section and ContentBlock patch fragments are materialized under that placement's `sections/<section-slug>/<block-slug>/index.ts`, while a separately verified Section added through a direct `sourcePatch.<sectionSlug>` reference receives a placement-local Section re-export. The original JSON-safe `production.sourcePatch` is validated by the trusted materializer against the actual imported Lesson `build.overrides()` result; never feed built `{id,base,locale}` as a Config patch, change the standalone Lesson, or produce `authoredCourseOverrides.ts`. New Sections may also be authored as inert `{ $create: 'course-section', source: { config, production? } }` entries at direct `sourcePatch.<sectionSlug>` keys, with the resulting placement recorded in `sourcePatch.children`. They are rendered under the same placement by the shared `materializeWorkflowSection` dispatcher used for ordinary Lesson Sections. Nested Scene blocks generate blocked Configurator sources alongside their Section and six pending executable draft files under the owning textbook's UUID-scoped `scenes/<bucket>/<uuid>/` tree. The Course planner seals both sets of paths in one plan; the publisher enforces complete six-file Scene groups, no-clobber and atomic source handoff, without registering or approving a Scene. Previously published Section references retain the `$ref: 'lesson-section'` form; the trusted dependency worker independently verifies them. A newly authored Section does not become executable input in the reviewed draft. Its generated source must still pass TypeScript, full Build validation, asset/Scene and publication gates before release.
- **Pending placements:** every reviewed new Lesson, Episode and Assessment slot has its **own** `<placement>/stub.ts` exporting `const <placement-slug> = defineLessonStub/defineEpisodeStub/defineAssessmentStub({id, slug})` and one actionable `TODO (BLOCKER)` specifying completion and agent-owned stub removal. Another actionable `TODO (BLOCKER)` is emitted **immediately above the matching import** in its owning parent `index.ts`. The immediate parent imports `{ <slug> }` directly from that local file; its root Config contains a direct `<slug>` placement (shorthand when the binding matches) and the complete reviewed root `children` order. The preview Configurator remains draft-only and blocked; an independent new Lesson UUID-addressed seed or Course-owned Episode/Assessment `draft.ts` preserves intent without being imported into the parent. An existing, verified Lesson is imported directly, **without** generating a stub. Never infer order from comments.
- **Shared languages:** emit a single Course-root `constants.ts` with source-only active `languages` and exported `Languages` type. `Course`, `Module` and `Chapter` index modules import from the root; only `constants.ts` records planned language restoration in one actionable TODO. Do not create `languages.ts` or duplicate active tuples in children.
- **Episode brief:** `production.focus/purpose` alone does not supply a reviewed playable Episode scenario. Pending Episodes stay explicitly blocked. Never invent a scenario, Scenes or full narrative on Stage 5.
- **Source preservation:** the trusted no-replay publisher deletes the exact pinned Stage 3 `draft.ts` and creates `index.ts` plus owner-allowlisted TS/Markdown files in the same Git commit. Exact original bytes remain in the reviewed commit/blob. Require pinned HEAD/blob, write-authorized actor, deterministic paths/UUIDs, no symlink/traversal, no existing file clobbers and non-force branch lease. Generated methodology is a **derived output**, not a second editable plan.

**Deployment boundary:** verify `.github/workflows/course-typed-materialization.yml` on default `develop`, its manual `workflow_dispatch` with `pr_number` and an actual authorized pinned Actions run before claiming operational materialization.

**Child source handoff and later integration:** Trusted Episode/Assessment gates pin the `stub.ts` blob SHA on both Course and child branches. The TypeScript AST verifier accepts only the exact slug-named `define*Stub({id,slug})` export, direct named import and ordered parent slot; it rejects executable/foreign stubs, forged IDs, ambiguity and changes to parent identity. The sealed, non-force source transaction creates only child-owned modules and **deletes only the reviewed child `draft.ts`**, preserving parent and stub byte-for-byte. Lesson Stage 6.1 has the same independent no-parent-mutation boundary. After resources, Scenes, upstream banks, locales and compatibility are verified, a Coding Agent performs explicit Course integration: replace the one immediate-parent stub import with the canonical real Configurator import, then delete just that owned `stub.ts`.

## Ordered placement inventory

The Stage 5 plan and trusted manifest include `inventory.lessons`, `inventory.episodes` and `inventory.assessments`, derived from actual renderer results and the complete reviewed Course order. Each row identifies its immutable UUID, slug, full placement and zero-based order path, source path, kind and factual handoff status. Repeated Lesson references have separate rows keyed by placement rather than UUID alone. This is source-planning evidence, not child PR creation, editorial approval or publication status.

The `placementSourcePath` for every row identifies its **immediate owning parent `index.ts`**; pending children have both `stubSourcePath` (the locally owned `stub.ts`) and an independent `sourcePath` (the authored `draft.ts` handoff, UUID-addressed for new Lessons). A reused Lesson's `sourcePath` is the immutable original Lesson `index.ts`; its `placementSourcePath` remains the immediate parent. An overridden Lesson additionally records `overrideSourcePath` pointing to its generated Course-owned placement `index.ts`, while the inventory retains the original `sourceExportName` and reviewed source SHA. Trusted manifest verification checks those placements against the sealed source bytes and rejects displaced, duplicate or unregistered stubs and handoffs. Source planning and production approval remain separate.
