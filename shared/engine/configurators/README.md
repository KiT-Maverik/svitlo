# Engine entity configurators

`configurators/` houses the `define*` authoring factories and Zod-backed schemas. The former `definitions/` directory has been folded into this directory. Legacy Course creators live separately in `configurators_old/`.

Private helper directories follow `_shared__<owningDirectory>` (for example `_shared__configurators` or `_shared__contentBlocks`) and are imported **only inside their owning directory**. Shared contracts needed by other groups belong in public `*.constants.ts`, `*.types.ts` or `*.schemas.ts` files, exported through the group's `index.ts`. Public indexes must not re-export a private helper directory.

The new Skill, SkillGroup, SkillDomain and AssessmentMethod factories intentionally use a minimal shape:

- `config.base` — non-localized fields such as `id`, `slug` and methodological description.
- `config.locales()` — localized fields such as names, titles and frontend descriptions.
- SkillGroup and SkillDomain configurators expose child configurators as slug-keyed `skill` and `group` maps.
- `*_Config_Schema` and `*_Props_Schema` validate the two representations.

All ten ContentBlock configurators now follow `defineText`: top-level identity (`id`, `slug`, `type`), nested `params` and `locale`, Zod-backed `*_Config_Schema` and `*_Props_Schema`, and `config.base` / `config.locales()` / `config.overrides` with per-block `override` and `disable` methods. A disabled ContentBlock deliberately replaces its parameter overrides with `{ disabled: true }`.

Every `define*` directory has an `index.ts` that exports its implementation and schemas; parent barrels export each directory once. Configurators expose `id` and `type` directly, plus `slug` where the authored entity has one. Their module-level `validate` functions are also exposed through `config.validate(config)`, while `config.base` continues to carry the publishing metadata.

`configuratorArrayToSlugMap([defineText(...), ...])` converts a list of configurators into a slug-keyed object, preserving literal slug types. It is useful for AI-authored content because authors need not duplicate slugs as object keys.

Checkpoint metadata has its own Zod schemas; nested content is typed but deliberately omitted from those schemas. The authored `content.items` object maps question slugs to `{ question: defineText(...), answer: { items, order }, check? }`. Answers may use any supported ContentBlock **except another Checkpoint**. The `config.validate` function performs parent Zod checks and verifies collection relationships (not child ContentBlock internals), then aggregates all failures in a `CheckpointValidationError` with `{ subject: { id, slug, type }, success: false, errors: [{ check, path, message }] }`. Orders are explicit and list each active item exactly once. `checkpoint.override.content.add(slug, item)` adds a question and appends its slug to the effective order; `disable(slugs)` records `false` for original question slugs and filters them from order; `order(slugs)` validates and replaces the entire effective order. Initial content is not modified. `false` is reserved for overrides (enforced at runtime), not authored `content.items`. Overrides are stored in `config.overrides.content`; the eventual `assemble()` will apply them and validate the resolved collection. Each nested ContentBlock retains its own override API.

Text ContentBlocks keep visible localized fragment values inline as `%_%id: personName; value: Maria%_%`. Optional `params.variables` is a camelCase-keyed map of styling rules, e.g. `{ personName: { applyStyle: ['variable', 'bold'] } }`; its keys are checked against every supplied text locale. No array entries or repeated `id` fields are needed, and the UI Kit selects each rule by key. Unlike Code, Text does not substitute values from a separate localized variables object.

Code ContentBlocks are **static, display-only source text**. `params.codeAsText` always contains the complete source string, not a file reference. An authored definition can read its neighboring source file via `readFileSync(new URL('./example.py', import.meta.url), 'utf8')`; Node throws if the file does not exist. The configurable `config.validate(config)` checks `%_%UPPER_SNAKE_CASE%_%` markers against the keys of `locale.variables`, a map from variable names to invariant or per-language strings, directly from `params.codeAsText`. The published Code response carries `codeAsText`, and the UI Kit presents it as highlighted, non-executable text while preserving whitespace. No Node file loader is needed inside Engine.

Lesson and all six current Section factories now follow the ContentBlock authoring lifecycle: top-level identity, `params` and `locale`, metadata-only `*_Config_Schema`/`*_Props_Schema`, `config.base`, `config.locales()`, `config.overrides`, `config.validate`, `override`, and `disable`. Lesson owns a `section: { items, order }` collection of Section configurators; every Section (including Quiz) owns `content: { items, order }` of ContentBlock configurators. The shared collection helper enforces camelCase slugs, key/child identity, and exact ordering without revalidating child metadata. Its `add/disable/order` overrides remain sparse; `false` disables a child only inside the overrides map, not authored content.

The optional Lesson `programId` marks course-owned, non-reusable Lessons; universal Lessons omit it. The Course hierarchy and Episode removal are explicitly deferred to the Course migration. Quiz `params.screen` references named Section content items by slug, rather than embedding ContentBlock configurators. Question, Flashcard, Course, legacy creators and publication consumers still need compatibility work. In particular, generators must resolve children and sparse overrides to JSON and must never serialize configurator methods. The future `assemble()` stage will revalidate merged/overridden output.
