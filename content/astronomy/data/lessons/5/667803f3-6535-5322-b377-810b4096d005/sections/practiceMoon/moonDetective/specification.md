# Детектив Місяця: формувальна вправа (НЕ scored Quiz)
Мета: перенести правило «те саме кулясте тіло / інша видима освітлена частина» на нові зображення; виявити плутанину з тінню Землі й орієнтацією без оцінювання mastery.
Доступні кейси: A — два спостереження одного диска в різні дні, спочатку приблизно половина освітлена, потім вузький серп; B — два спостереження того самого диска в різні дні, спочатку вузький серп, потім майже повний диск; C — зображення приблизно тієї самої освітленої частки, повернуте відносно іншого спостереження; D — спершу майже повний освітлений диск, а через кілька днів менша освітлена частина того самого диска (спадання, без вимоги терміна «спадний Місяць»). Жоден кейс не потребує називати фазу, читати дати напам'ять чи знати орбітальну схему. Для A/B правильний сенс «Змінилося, скільки освітленої частини видно із Землі», а не фізична форма. Для C — «Це той самий круглий Місяць; його вигляд може бути повернутий на зображенні». Для D — optionWaning, тобто освітленої поверхні з Землі стало видно менше і схожі вигляди повторюються.
Подача: один кейс на екрані, заголовок та короткий опис; показати диск із незалежною доступною словесною характеристикою. Запитання «Яке пояснення підходить?»; альтернативи локалізовані в locale.value (optionVisibleLight/optionChangedBody/optionEarthShadow/optionSameBody/optionWaning), кількість у конкретному кейсі невелика. Кнопки мають очевидні accessible names, великі цілі дотику та клавіатурний фокус. Вибір не оцінюється числовими балами.
Матриця вибору (кожен кейс показує лише ці три варіанти, у доступному для клавіатури текстовому списку; порядок візуального розміщення не визначає правильність):
  A (половина -> серп): optionVisibleLight -> feedbackCorrect [правильно]; optionChangedBody -> feedbackTryAgain [хибно]; optionEarthShadow -> feedbackShadow [хибно].
  B (серп -> майже повний): optionVisibleLight -> feedbackCorrect [правильно]; optionChangedBody -> feedbackTryAgain [хибно]; optionEarthShadow -> feedbackShadow [хибно].
  C (однакова частка, інший поворот): optionSameBody -> feedbackOrientation [правильно]; optionChangedBody -> feedbackTryAgain [хибно]; optionVisibleLight -> feedbackSameAmount [хибно: у цьому кейсі розмір видимої світлої частини той самий].
  D (майже повний -> менша частка): optionWaning -> feedbackWaning [правильно]; optionChangedBody -> feedbackTryAgain [хибно]; optionEarthShadow -> feedbackShadow [хибно]. Не показувати optionVisibleLight у D: це загальне твердження тут теж було б правдою і створило б дві правильні відповіді.
Зворотний зв'язок: дотримуватися точної матриці A–D. Після правильного вибору показати відповідний feedbackCorrect / feedbackOrientation / feedbackWaning і дозволити перейти далі. Після хибного — feedbackTryAgain / feedbackShadow / feedbackSameAmount; залишити той самий кейс, дати переглянути пояснення й натиснути retry для іншої спроби без осуду. При повторних помилках показувати те саме пояснення, не блокувати повернення або перехід до текстового варіанта. Не застосовувати вимоги Question Bank, Quiz API, таймер, оцінки чи градацію успіху до цієї сцени; noScore видно весь час.
Навігація/стан: початковий кейс A без вибору; далі B -> C -> D. nextCase доступна після правильної відповіді у кейсах A/B/C; skipCase без підтвердження переходить до наступного кейсу і нічого не зараховує. У кейсі D після правильної відповіді доступна finish, а skipCase одразу завершує спробу без позначки «успіх». previousCase доступна з B/C/D навіть до відповіді; повернення відкриває попередній кейс для нової спроби без балів. retry доступна після помилки, очищує поточний вибір і знову активує відповіді. skipCase явно переходить до наступного кейсу, а на D — до завершення; finish доступна також достроково як добровільний вихід до verbalCases, без позначки «успіх». Після переходу між кейсами клавіатурний фокус потрапляє на заголовок нового кейсу; зворотний зв'язок надходить у видимий текст і ненав'язливий live-status без автоматичного стрибка фокуса. На завершенні показати noScore та можливість пройти verbalCases; Scene не змінює graded Quiz чи глобальний Lesson completion.
Демонстрація для розробника: незмінний розмір диска в усіх кейсах; у A/B обов'язково показати по дві позначені в часовому порядку картинки одного диска (зменшення освітленої частини в A, збільшення в B), лише поворот у C, а в D порівняння двох послідовних спостережень зі зменшенням світлої частки. Не виводити висновок про фазу тільки за лівим/правим краєм або кольором. В окремому screen-reader тексті описати умову й наслідок вибору, а помилки оголошувати доброзичливо.
Доступний рівноцінний шлях: альтернативні verbalCases і verbalFeedback нижче є незалежними Markdown-блоками цієї Section, які можна виконати усно, за допомогою екранного читача або клавіатури без візуального розпізнавання. У разі відсутньої реєстрації Scene, помилки/затримки JS-чанка, офлайн-недоступності або неможливості керувати графікою Stage 6 має локально ізолювати збій (поточний UI Kit Scene без обгортки кидає виняток), не ховати Markdown нижче, показати локалізовані unavailable/continueWithoutScene, оголосити короткий стан і за дією перейти фокусом до verbalCases без переходу до Quiz чи втрати навігації. Навіть при справній Scene текстові кейси лишаються доступні без обов'язкових натискань. Це план відновлення для реалізації/тестів, не вже готовий UI. Не показувати лише колірні відмінності. Без анімації за reduced-motion. Повністю офлайн локальні SVG/HTML, не завантажувати нічого із мережі.
Технологія: авторинг і Scene Build контракт є, але конкретна Scene та її реєстрація не реалізовані в цьому PR. Stage 6 повинен додати код, тест кейсів/відгуку, клавіатури, невізуальної альтернативи й локалізацій.
