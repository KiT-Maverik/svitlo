# Scene — конструктор запису
Мета: власний запис дитини з п'ятьма полями — що, коли, де/звідки, як, умови. Це формувальне свідчення, не scored Quiz; автоматично оцінювати правдивість власних слів не можна.
Джерела: дитина обирає «моє безпечне спостереження» або «реальне фото та підпис NASA». Перевірена сторінка NASA «Supermoon in Washington»: https://www.nasa.gov/image-article/supermoon-washington/; фотограф NASA/Bill Ingalls; історична дата 23 червня 2013 року; у підписі вказано, що Місяць сходить за Монументом Вашингтона у Вашингтоні, США. Час доби, точна година, погода, кількість хмар і точна позиція фотографа в цьому підписі НЕ вказані — не домислювати. Копія перевірених фактів і чітке джерело повністю записані у `recordTask` і `recordChecklist` для офлайн-читання; зовнішнє посилання — лише засіб перевірити походження, а не навчальна залежність. На Stage 6 можна окремо вирішити питання фізичного зображення, ліцензії/відтворення, локального пакування, затвердження його alt і кредитів; поки що жоден Image/asset ID не створено. Вигаданий опис із `workedRecord` залишається тільки демонстрацією структури, не джерелом індивідуального доказового запису.
Стани: chooseSource -> editFields -> preview -> revise/complete. П'ять незалежних семантичних полів з підписами, готові слова/значки з текстом і можливість власних слів. Мінімальне педагогічне свідчення: конкретне, обґрунтоване за обраним джерелом `what`; явно обраний режим і чесний provenance (`де або яке джерело`); спосіб `how`; час/дата і умови заповнюються лише за відомостями або як «не вказано». Для NASA дата 23 червня 2013 року відома, точна година й погода — ні. «Не вказано» не може заміняти саму деталь `what` або атрибуцію джерела: якщо їх немає, не позначати запис змістовно завершеним, а дати пояснювальну підказку. Не розпізнавати автоматично правдивість власних спогадів і не здійснювати keyword-scoring вільного тексту; дозволити самооцінку або обговорення з помічником. Для плутанини «бачив/прочитав» — запит виправити джерело; для вигаданої причини — прохання залишити лише перевірювану деталь. Перегляд дозволяє виправлення; очищення потребує підтвердження. Всі повідомлення є формувальними, не виставляють grades або mastery.
Немає балів, таймера, GPS, камери, вимоги мікрофона, зовнішнього API чи обіцянки збереження між сесіями. Доступні keyboard/touch/screen reader, focus order, текстовий live feedback, 320px, RTL, reduced motion, contrast; не покладатися тільки на колір чи піктограму. Для тих, хто ще не читає, джерело NASA, п'ять запитань і підсумок запису мають бути доступні для прослуховування: Stage 6 має реалізувати й перевірити доступне офлайн-озвучення/читання (паковану локалізовану начитку або реально підтримуваний TTS) чи забезпечити чітко позначений маршрут із читанням помічником без обіцянки самостійного голосового доступу. Не вигадувати audio asset ID або гарантію офлайн TTS на цьому етапі. Кнопка «Прочитати запис» без озвучення повинна показувати доступний текст для читання/скрінридера, а не обіцяти голос. Всі тексти з locale.value.
Повноцінний варіант без Scene — самодостатні `recordTask` (верифікований NASA-підпис) і `recordChecklist` (той самий підпис, джерело та поля); працює з текстом без Scene, інтернету, особистих даних або необов'язкового медіафайла. Source-mode rules для слів/значків: у режимі NASA пропонувати як підтверджені лише Місяць, дату 23 червня 2013, місце/джерело NASA/Bill Ingalls і читання підпису; час доби, хмарність і погодні умови — тільки «не вказано». Не пропонувати в NASA-режимі «хмари», «ясно», «хмарно», «ранок/день/вечір» як підтверджені варіанти. У режимі власного спостереження дозволяти загальні слова, але не вважати їх автоматично правдивими. При зміні режиму не переносити попередні непідтверджені відповіді мовчки: показати їх як такі, що потребують перевірки, запропонувати змінити чи очистити; для довільного тексту давати пояснення та самоперевірку, не вгадувати наукову достовірність. Реальну React-реалізацію, реєстрацію UUID і технічні тести роблять лише на Stage 6.
