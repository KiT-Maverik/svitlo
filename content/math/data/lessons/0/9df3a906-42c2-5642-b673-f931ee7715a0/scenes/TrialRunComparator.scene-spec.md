## Educational purpose and intended web interaction

Compare outcome frequencies from two finite runs of the same fair random experiment and explain why differing counts can arise without any change to the experiment's possible outcomes, conditions or chances.

A deterministic _illustration of possible outcome sequences_, not a fake live-randomness proof: a labelled equal-sector spinner remains visibly unchanged while the learner reveals Run A and Run B as fixed recorded sequences of ten spins. Counts update one by one with blue/yellow labels; after both, an optional third panel deliberately shows a changed spinner and asks which conditions changed.

**Self-contained design:** One independently initializable, prop-free Scene root owns all preset data, controls, explanations and interaction state. Multiple Section placements must not rely on props or state inherited from other Scenes. No invented renderer registration, engine hooks, scoring or persistence are authorized by this document.

## Exact factual models and required states

| Preset/state       | Model shown or described                                                           | Correct observation and explanatory result             |
| ------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **Shared setup**   | Two equal-size angular sectors, blue and yellow; uniform pointer direction assumed | Both colors possible and equally likely per spin       |
| **Run A outcomes** | Blue, Blue, Yellow, Blue, Blue, Yellow, Blue, Blue, Yellow, Blue                   | 7 blue and 3 yellow; total 10                          |
| **Changed setup**  | Four equal-sized sectors, 3 blue and 1 yellow; uniform pointer direction assumed   | Chances changed; 3 blue sectors rather than 1 of 2     |
| **Incomplete run** | Any prefix of recorded examples shorter than ten trials                            | Subtotal of blue+yellow equals revealed trial count    |
| **Run B outcomes** | Yellow, Blue, Yellow, Yellow, Blue, Yellow, Blue, Yellow, Yellow, Blue             | 4 blue and 6 yellow; total 10                          |
| **Run comparison** | Run A 7 blue/3 yellow; Run B 4 blue/6 yellow; same spinner rule                    | Counts differ across runs despite unchanged conditions |

**Validity boundary:** Two explicit ten-trial sequences of a fixed two-equal-sector uniformly random spinner, per-color frequency comparisons, and one changed-conditions counterexample. Count outcomes, identify constant/changing factors and compare two runs; do not introduce numeric probability estimates, significance testing, independence theorems, law of large numbers, hypothesis testing, percentages or claims about statistical bias from tiny samples.

## Learner actions, transitions and recovery

Choose 'Reveal next trial', 'Show Run A', 'Show Run B', 'Compare fixed conditions', 'Show changed experiment', or Reset. Keep spinner conditions visible and identical throughout A/B. Each trial's prewritten example outcome advances counts; never claim these outcomes were generated by a live fair RNG or proved underlying probabilities. No props, global state, scoring, timers or network.

1. Start from one fully specified state with all its reference data visible or available via the text equivalent (whole, units, tick scale, key, or experimental conditions).
2. Let the learner predict before an automatic answer reveal where useful, but always permit a voluntary request for a worked explanation without an assessment gate.
3. For each action, preserve mathematical invariants, update the model deterministically and expose the new state and relevant numbers using both a visible and a structured accessible description.
4. Incorrect prediction or choice: explain what contradicts the claim (actual part size, the hand's position, chart's row count, or sample-space evidence) and allow an undo, retry or reset, without score or penalty.
5. Switch presets without leaking state between separate Scene instances; reset returns the current Scene to the documented initial state. A later independent transfer must hide the worked result until prediction or voluntary reveal, not hide the evidence itself.
6. No essential knowledge depends on autoplay motion, sound, fixed response time, probability of hitting a random state, or fine motor skill.

## Detailed explanatory feedback

- **Fix the spinner, count the spins: Five each guaranteed.** “Each spin could be either color. Equal chances do not force equal counts in a short set of spins.”
- **Fix the spinner, count the spins: Seven blue changes chance.** “The spinner stayed the same; seven is what we observed in these ten example outcomes, not a new spinner rule.”
- **Two runs, different totals by color: Counts must match.** “The experiment conditions are the same, but the outcomes are not predetermined. A short run can have different color totals.”
- **Two runs, different totals by color: Run B 5/5.** “Count the blue entries in the example sequence carefully: there are four blue and six yellow.”
- **Two runs, different totals by color: Spinner biased now.** “We observed different totals; the displayed spinner and uniform assumption did not change. These two examples alone do not prove a changed chance.”
- **Different sample, or different experiment?: No rule change.** “The blue part changed from half to three quarters of the circle. That changes what the spinner can favor.”
- **Different sample, or different experiment?: Same as Run B.** “Run B used the original half-blue spinner. This new design favors blue; do not treat the conditions as identical.”
- **A fresh pair of short runs: Must change spinner.** “Neither run changes the blue/yellow half-spinner. Different chance outcomes can occur under the same conditions.”
- **A fresh pair of short runs: Second run proves yellow favored.** “Four yellows in six spins are observed outcomes; they do not change how much of the spinner is yellow.”

**Model limitations:** All examples are explicitly constrained to the conditions above. Do not extrapolate to unsupported operations or claim a simulation proves mastery or statistical generalizations. For the probability Scene, recorded illustrative sequences must never be described as a live random experiment that empirically verified fairness.

## Accessible equivalent path

A keyboard-operable textual table lists each of ten outcomes in Run A and Run B and the numeric frequency after each reveal, with an explicit note that both are _possible examples_. An equally valid reduced-motion state shows complete lists immediately. A separate textual changed-condition card says 'original one blue of two equal sectors; changed three blue of four equal sectors'.

All key interactions must be fully operable with native labelled keyboard/touch controls. Screen readers need a chronological, understandable announcement of changes without a flood of redundant narration. Use text labels and descriptive math/value captions rather than color or position alone. Include visible focus, sensible order, reduced-motion/static states, adequate touch sizing and narrow-screen alternatives.

## Locale / RTL / offline / weak-device requirements

Genuine meaning-preserving translations of every label, narration, option, alt description and explanatory message are required in every supported locale; **do not implement silent English fallbacks, fake translations or missing dictionaries**. Distinguish mathematical meaning from visual LTR/RTL arrangement; fraction slash interpretation, clock hands and spinner probabilities must not be reversed by naive mirroring. The same lesson functionality must remain available on low-power/mobile devices and offline after complete package download. These are implementation acceptance criteria, not features supplied by this specification.
