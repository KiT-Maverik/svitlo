## Section 1 — Predict whether two amounts match

1. **text**: “On the first tray, three red counters and two blue counters. On the second, five plain counters. Are the amounts the same?” The color is irrelevant to the total.
2. **scene (proposed)**: [Equality Workbench](./scenes/equalityWorkbench.scene-spec.md). The learner counts each tray, predicts “same amount” or “different amount”, then reveals the totals.
3. **text**: “Both show five. The symbol = means both sides have the same value.” Mistake feedback: “Count all the counters on each side, regardless of color.”

## Section 2 — Equality does not just announce the answer

1. **markdown**: “3 + 2 = 4 + 1 is true: five on each side. 5 = 2 + 3 is also true: the answer need not be on the right.”
2. **scene (proposed)**: Workbench variation compares 3 + 2 with 4 + 1; independently reveal each side’s total. The child may select a verbal explanation. If wrong: “These groups are arranged differently, but both have five.”
3. **text**: “What does the sign say?” After choosing, reveal “The values match,” not “Now calculate.”

## Section 3 — Repair a false equality

1. **markdown**: “4 + 2 = 4 + 3 is not true: six is not seven.”
2. **scene (proposed)**: Change the number of counters on one side to make it equal. Adding one counter to the first side gives 4 + 3 = 4 + 3. A wrong response gets numeric feedback: “The first side still has six and the second has seven.”
3. **text**: “We changed an amount. The equality is true only after both values match.”

## Section 4 — Independent transfer

1. **text**: “Someone says 6 = 1 + 5 is wrong because the answer is on the left. Do you agree? Explain, or choose ‘six on each side’ or ‘the sign needs an answer on the right’.”
2. **text**: After response or on-demand reveal: “Six on the left, six on the right. It is true.” A mistaken explanation triggers the same concrete count.
3. **markdown**: “Remember: **= means the values on both sides match.**”
