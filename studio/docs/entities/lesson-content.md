# Lesson Content

**Entity category:** historical Screenwriter-owned editorial plan for a Lesson. **Not a new-work source:** [Create Lesson Flow](../../skills/lesson-workflow/create-lesson-flow.skill.md) now uses one progressive typed Lesson `index.ts`: Stage 1 `LessonWorkflowStage1`, Stage 2 `LessonWorkflowStage2`, with Stages 3–5 reviewing that same object; the old `content.yaml` and its hand-maintained schema are retained only for an audited, non-destructive legacy migration. Do not generate new `content.yaml` or represent it as a current canonical authoring requirement.

## Historical editorial format (migration reference only)

Earlier Lessons used two independent documents: a Methodologist `methodology.md` for educational intent and Screenwriter `content.yaml` for Section/ContentBlock plans, source locale, assessment placement and media handoffs. This is **not** a current new-work protocol or a second canonical source.

Historical path: `content/<textbook>/data/lessons/<last-uuid-hex>/<lesson-uuid>/content.yaml`. Preserve original documents and SHA-linked independent reviews when migrating into the single, typed Lesson `index.ts` `config` + `production`; never silently truncate approved prose, fabricate translations, or assume a legacy `status: approved` marker equals today's independent review.

For **new** Lesson authoring, [Create Lesson Flow](../../skills/lesson-workflow/create-lesson-flow.skill.md) owns Stages 1–5 on the typed `index.ts`. Methodologist `production.methodology` defines outcomes/subject/assessment obligations, Screenwriter authors actual ordered Section and ContentBlock `config` plus `production` specifications, and independent reviewers record decisions in the **Lesson Draft PR**. The integrated #775 **trusted typed** Stage 6.1 source materializer consumes only the reviewed `LessonWorkflowMaterializerInput`, generates real modular source and derived `methodology.md`, with create-only/no-clobber behavior. The removed YAML Finalize Lesson tool is not available as a fallback. Independent assessment banks use their own typed `questions/index.ts` and `flashcards/index.ts` sources, never fields on Lesson Config.

The former `lesson-content.schema.json` and Engine YAML editor schemas are retired. Historical `content.yaml` files may be read for separately authorized source/provenance transfer, but they are not live validation schemas. The actual `LessonWorkflowStage1`/`LessonWorkflowStage2` TypeScript contracts and Engine Config/Zod define new editorial source validity.

## Section and Quiz contracts

Regular Sections contain ordered ContentBlocks (current discriminant `type`; no old `blockType`). Markdown ContentBlocks support inline and display LaTeX; see [Markdown formulas](./markdown-content-block.md) for accessibility, syntax and translation guidance. Every typed Stage 2 block has stable editorial key, type, learner-facing content and relevant `production` purpose/specification, accessibility and readiness. A Screenwriter can propose a new Scene or media dependency but cannot claim that runtime support already exists.

**A Quiz is a Section, never a ContentBlock.** A Lesson may have **no Quiz, one Quiz or several** according to the approved Methodologist `assessmentPlan`. Each Quiz Section references a unique approved `assessmentPlanKey` and repeats the exact target Skill IDs and `requiredAssessmentMethods` from that requirement. `AssessmentMethodKey` expresses a cognitive operation, not the UI Question type. The Assessment Architect owns Question correctness, distractors, grading and mastery; the Screenwriter places the Quiz and explains its teaching context.

Neither historical `content.yaml` nor the new Stage 2 typed `index.ts` is a runtime Lesson Props object or a direct `defineLesson` Config. The trusted **typed** Stage 6.1 source materializer composes the final `define*` modules from reviewed plain Config-shaped nodes, not infer all authoring semantics from runtime Props. [Implement Scene](../../skills/lesson-workflow/implement-scene.skill.md) handles only approved Scene React behavior, tests, integration and source-locale text; translation agents complete other languages. [Lesson](./lesson.md), [Section](./section.md) and [Lesson editorial artifacts](../architecture/lesson-editorial-document.md) establish boundaries and review policy.

## Quest editorial blueprint

[Quest](./quest.md) is a planned Section presentation option for autonomous interactive workspaces with branching Stage media and Task Scenes. When proposing a Quest, describe the start Stage, initial Task, every branch/reaction, pedagogical intent, feedback, Task Scene behavior, mandatory media alternatives, captions/transcripts, nonvisual interaction, reduced-motion and offline prerequisites. It is not a scored Quiz, nor an Episode-level storyline introduced into a standalone Lesson. The editorial plan schema can express a Quest proposal, but **the runtime Section registration and UI are not wired yet**; classify production as pending platform capability.
