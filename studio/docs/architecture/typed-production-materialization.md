# Typed production materialization

The canonical editorial input for Course, Episode, Lesson, Question Bank and Flashcard Bank is a single Stage-specific TypeScript object. Editorial inputs and materialized Configurators have distinct responsibilities; the trusted source-materialization workflows do not publish runtime Props.

## Entity-owned source flows

- **Course:** Stages 1–3 progressively author `draft.ts` using `CourseWorkflowStage1/2/3`; independent Stage 4 corrects and reviews the final typed source at a pinned SHA. Authorized Stage 5 consumes the same reviewed bytes and currently emits Course/Module/Chapter source, Lesson seed drafts and Episode handoffs; proposed Course-owned Assessment placeholders/inventory require #826 integration after #823. **Stage 6 Verify Questions Readiness** coordinates real independently authored Lesson-owned Question Banks and selected UUID/locale prerequisites, without duplicate bank materialization. **Stage 7 Design Assessments** is **conditional**: explicitly Skip in the Course PR with all-false Course/Module/Chapter decisions and zero Assessment placements, otherwise coordinate the separate Assessment Flow. Stages **8–9** own Course translations/review; **Stage 10** is mandatory human QA of the integrated Course with all required child entities. The same `svitlo-course-flow:v1` Course PR tracker records all ten stages; inventory placement tables are separate managed content. Stage 6/7 are editorial coordination, not new Course Source Configurator stages or alternative materialization commands. See the canonical Course Skill for acceptance and evidence.
- **Episode:** The Course allocates the exact immutable placement, UUID, reviewed intent and locale plan. The Episode-owned Stage 1–2 `draft.ts` is reviewed at Stages 3–4, consumed atomically at trusted Stage 5, then completed at Stages 6–8; human Media Generation and QA at Stages 9–10 are independent release gates. See [Episode Flow](../../skills/episode-workflow/create-episode-flow.skill.md).
- **Lesson:** Independent authoring contract; authorized Stage 1 completes `LessonWorkflowStage1` from any supplied editorial material (including a Course seed), preserving existing UUID and replacing the seed at the same `draft.ts`. No cross-workflow imports or automatic conversion. Stage 1/2 editorial `draft.ts` (`LessonWorkflowStage2` at final handoff) is reviewed at Stages 3–5. Authorized Stage 6.1 consumes the valid pinned draft atomically without parsing editorial or Course provenance evidence and creates `index.ts` and modular `defineLesson`, Sections and Blocks. Scene implementations/assets, Questions, Flashcards, translations and separate publications are not invented.
- **Questions/Flashcards:** Independently authored Stage 1–3 TypeScript banks, source-SHA-pinned independent Stage 4 reviews and trusted Stage 5 materialization. The draft deletion and creation of final `questions/index.ts` or `flashcards/index.ts` transition are no-clobber and atomic. Real all-bank resources, selected Sections, locales and media are independently verified.

Engine's concrete source materializers live under `shared/engine/generators/materializers/`; trusted commands live under `scripts/ci/{courseMaterialization,episodeMaterialization,lessonMaterialization,bankMaterialization}/`. Candidate PR TypeScript is statically inspected as inert data. Only default-branch trusted code executes, with read-only analyze and privileged manifest-checked publish separated. Git source/HEAD SHA, branch lease, path/symlink restrictions and exact file bytes are required. All five workflows require an explicit authorized invocation and valid pinned typed source. None parses PR descriptions, editorial checklists, markers, review evidence or verdicts as an eligibility condition. [Independent review](../../rules/independent-review.md) and stage tracking remain editorial responsibilities in the existing entity PR. Real entity ownership and required technical relationships are derived from canonical source and Git topology, not prose. No Configurator `build.files()` is introduced.

## Publication and rollout boundaries

The separate `generateLessonProps`, `generateCourseProps` and `generateAssessmentResources` scripts consume **completed** typed Configurators. All emitted TypeScript must be syntactically and semantically valid against current contracts. Use valid typed placeholders and explicit `TODO (BLOCKER)` markers for legitimately unfinished production resources where applicable; editorial handoffs remain typed drafts, not runtime Configurators. A source scaffold or reviewed Stage 3 plan is not publishable. `TODO (BLOCKER):`, `TODO(asset)`, Nil UUIDs, missing real selections, physical assets, implemented Scenes or languages fail publication as appropriate. A known Course/Question/Flashcard bank does not imply the associated Section is complete.

The exact top-level PR commands are `/course materialize`, `/episode materialize`, `/lesson materialize`, `/questions materialize` and `/flashcards materialize`. No format selector is supported. Before invoking a materialization command, verify the corresponding trusted workflow exists on the default branch. Verify an authorized Actions run on safe reviewed inputs, its pinned source SHAs and resulting commit before declaring the pipeline operational.

## Historical source preservation

The 109 `content/math/data/lessons/**/lesson.yaml` files are **historical user-authored source** and were preserved. They are not instructions to regenerate a Lesson using a deleted converter. Migrating any such Lesson requires explicit non-destructive provenance and semantic review of its actual authored material; this infrastructure cleanup does not silently convert or delete editorial source. Prior prototypes and removed scripts remain recoverable from Git history. Do not restore their generated editor schemas or treat archived YAML as a second source of truth.

Review the current [Course Flow](../../skills/course-workflow/create-course-flow.skill.md), [Lesson Flow](../../skills/lesson-workflow/create-lesson-flow.skill.md), [Questions Flow](../../skills/lesson-workflow/create-questions-flow.skill.md) and [Flashcards Flow](../../skills/lesson-workflow/create-flashcards-flow.skill.md) for stage-specific approval and authoring rules.

All editorial roots use exactly one `draft.ts` and completed roots use `index.ts` (supported standalone Lesson `.data.ts` remains valid). Publishers never load editorial sources; draft-mode validation may omit unfinished roots, whereas strict release rejects unfinished or ambiguous roots. Materialization consumes the approved draft in the same Git commit that creates the final source. Technical provenance is the immutable consumed source commit and blob, not an extra live archive or review-status record.
