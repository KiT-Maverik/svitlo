# Course Workflow

**Canonical production procedure:** [Create Course Flow](./create-course-flow.skill.md). Course production has **ten stages, one entity-owned Course PR and one evolving TypeScript Course planning object**. Use the canonical `draft.ts` until materialization; do not create a second plan, `toc.yaml`, `config.yaml`, review PR, production Issue, stage-status file or artifact ledger. The [Course entity](../../docs/entities/course.md) supplies entity semantics. Select Personas by stage in the table below; load additional specialists only when their expertise is needed.

## One typed source and one production record

- **Stages 1–3:** keep one Course source object at its canonical UUID-addressed Course `draft.ts`, refining the same `config` and `production` tree. Import `CourseWorkflowStage1`, `CourseWorkflowStage2` and `CourseWorkflowStage3` from `@svitlo/engine/build` and use the relevant `satisfies` operator. During Stage 4, before final reinspection, CI evidence and sign-off, the **same corrected Stage 3 export** must use `satisfies CourseWorkflowMaterializerInput` (alias to Stage 3, no additional authored stage or schema). The [Engine type contract](../../../shared/engine/types/workflow/courseWorkflow.types.ts) defines the actual structure; its [typecheck fixtures](../../../shared/engine/types/workflow/courseWorkflow.typecheck.ts) show working positive/negative type examples.
- **Stage 4:** a separate-context Methodologist/Assessment Architect reviews the _actual Stage 3 TS source_ at an exact SHA, commits any in-scope corrections immediately to the **same Course PR**, finalizes the single exported materializer input as specified in the canonical Skill, verifies the corrected final source and records a single final SHA/verdict. There is no Stage 4 TypeScript data contract or second independent methodological review.
- **PR:** the existing Course PR description owns all ten stage checkboxes and revision-pinned review/handoff evidence. Git holds the authored source. Draft is the active-editing state; **Ready for review is the automatic handoff after authorized work is complete**, not a merge authorization. Follow [CI lifecycle](../../rules/ci-workflow.md).
- **Stage 5:** requires specific authorization and a **verified, implemented typed** Course materializer accepting `CourseWorkflowMaterializerInput`. It consumes the exact reviewed bytes without source edits. All generated TypeScript must satisfy current contracts; unfinished resources use typed placeholders and explicit `TODO (BLOCKER)` where applicable. It creates deterministic **derived** human-readable `methodology.md` in stable heading order for Course/Module/Chapter; Markdown is never a second editable source. For each `kind: 'new'` placement, it creates a UUID-addressed **`draft.ts satisfies CourseWorkflowLessonSeed`** containing allocated identity, substantive Course proposal, all four assessment decisions and Course-derived language context: **no `defineLesson`, Section drafts, `Not implemented` placeholders, Quiz/Flashcards selection IDs, or Lesson PR**. Those belong to separately authorized later Lesson production. Lesson Stage 1 independently completes its own `LessonWorkflowStage1` contract at the same draft path, without requiring a Course seed. The newly created Lesson's own derived `methodology.md` is produced only by its **later Lesson materializer**, not alongside the Course Stage 5 handoff. Child Questions/Flashcards also start as typed Stage 1 source handoffs rather than full banks. Follow the [trusted Stage 5 runbook](../../../scripts/ci/courseMaterialization/README.md) and verify actual default-branch workflow availability, source integrity and authorization before invoking. Stage 4 review remains an editorial responsibility; no description or verdict is parsed by the materializer. New Lesson UUIDs/handoffs belong to Stage 5, never Stage 3. Every new/**existing** Lesson placement requires four independent `production.assessment` booleans: `questionBankRequired`, `flashcardBankRequired`, `quizSectionRequired`, `flashcardsSectionRequired`. Bank need is distinct from Section need; `quizRequiredForCompletion: true` separately implies a completed enabled Quiz Section. It does **not** start Lesson Production.
- **Stage 6 — Questions readiness:** coordinate actual required Lesson-owned Question Banks and reviewed Question UUID/locale dependencies before designing Assessments. Do not duplicate the independent [Questions Flow](../lesson-workflow/create-questions-flow.skill.md), author banks inside the Course, or automatically create child PRs.
- **Stage 7 — Design Assessments (conditional):** if any Course/Module/Chapter owns an Assessment slot or explicitly requires a direct Assessment, coordinate its separately authorized [Assessment Flow](../assessment-workflow/create-assessment-flow.skill.md) with verified upstream/additional Lessons and reviewed Question Banks. If **every** parent explicitly sets `production.assessment.required: false` **and** the entire Course has zero Assessment slots, mark **Skipped** with source-SHA evidence in the existing Course PR tracker. A missing decision or contradictory slot is not a skip. The final Stage 5 Assessment inventory and PR-description placement table remain a separate pending implementation task in #826, overlapping #823.
- **Stages 8–9:** authorized Course-owned translations and independent linguistic review occur in the **same entity PR** and do not certify independently authored Lessons, Episodes or Assessments. Follow [Translation Workflow](../translation-workflow/README.md). Stage 10 human QA verifies all required child dependencies.

## Ten stages

| Stage | Responsible role | Acceptance boundary |
| --- | --- | --- |
| 1. Create Course Methodology | Methodologist | Complete Stage 1 methodology and explicit Course-level Assessment requirement decision (contract integration pending #823) |
| 2. Design Course Structure | Methodologist | Ordered Course/Module/Chapter hierarchy with direct Assessment intent, nested placements and lesson/episode slots |
| 3. Design & Match Lessons | Methodologist + Assessment Architect | Resolve instructional Lesson slots, including ownership of Questions/Flashcards and Assessment prerequisite Lesson dependencies |
| 4. Review Course Plan | Independent Methodologist + Assessment Architect | Correct and verify the final Stage 3 source in a separate context; pin the final revision and verdict |
| 5. Materialize Course | Coding Agent | Authorized reviewed input → Course sources, immutable placements, Lesson/Episode handoffs and pending Assessment placeholders/inventory (Assessment implementation pending) |
| 6. Verify Questions Readiness | Learning Assessment Architect | Verify required real Lesson-owned Question Banks, reviewed source UUIDs, provenance, locales and Assessment consumption dependencies; no duplicate Question authoring |
| 7. Design Assessments (conditional) | Learning Assessment Architect + Methodologist | For each actual Course/Module/Chapter Assessment, coordinate reviewed design in its Assessment-owned flow; or record **Skipped** with all false decisions, zero slots and source SHA |
| 8. Translate Course | Technical Translator | Authored Course-local target locale fields only; independent child locales stay with their owners |
| 9. Review Course Translations | Independent Technical Translator | Source-SHA-pinned semantic/linguistic approval for each required Course locale |
| 10. QA — Human | Human reviewer | Explicit human pass on actual integrated Course with complete required Assessment/Lesson/Episode dependencies |

Stage 10 is mandatory human-owned integrated Course QA, after Stage 9. Agents and CI provide evidence, not approval. See the canonical Skill for the human handoff, checklist and revision-specific verdict. Episode Stage 10 QA is separate.

## Operational boundary

Verify the trusted workflow on the default branch and the actual authorized run, pinned source SHAs and generated commit before declaring successful materialization.

For detailed methodology, partial/final acceptance, Assessment upstream/additional Lesson dependencies, PR tracker format and Stage 5–10 handoffs, consult only [Create Course Flow](./create-course-flow.skill.md).
