# Course Workflow

**Canonical production procedure:** [Create Course Flow](./create-course-flow.skill.md). Course production has **seven stages, one entity-owned Course PR and one evolving TypeScript Course planning object**. This replaces the old temporary `course.yaml` editorial source; it does not create a second plan, `toc.yaml`, `config.yaml`, review PR, production Issue, stage-status file or artifact ledger. The [Course entity](../../docs/entities/course.md), [Methodologist](../../personas/methodist.persona.md) and [Learning Assessment Architect](../../personas/learning-assessment-architect.persona.md) supply the domain requirements.

## One typed source and one production record

- **Stages 1–3:** keep one Course source object at its canonical UUID-addressed Course location, refining the same `config` and `production` tree. Import `CourseWorkflowStage1`, `CourseWorkflowStage2` and `CourseWorkflowStage3` from `@svitlo/engine/build` and use the relevant `satisfies` operator. Immediately before authorized Stage 5, the **same corrected Stage 3 source** must also `satisfies CourseWorkflowMaterializerInput` (alias to Stage 3, no additional authored stage or schema). The [Engine type contract](../../../shared/engine/types/workflow/courseWorkflow.types.ts) defines the actual structure; its [typecheck fixtures](../../../shared/engine/types/workflow/courseWorkflow.typecheck.ts) show working positive/negative type examples.
- **Stage 4:** a separate-context Methodologist/Assessment Architect reviews the *actual Stage 3 TS source* at an exact SHA, commits any in-scope corrections immediately to the **same Course PR**, verifies the corrected final source and records a single final SHA/verdict. There is no Stage 4 TypeScript data contract or second independent methodological review.
- **PR:** the existing Course PR description owns all seven stage checkboxes and revision-pinned review/handoff evidence. Git holds the authored source. Draft is the active-editing state; **Ready for review is the automatic handoff after authorized work is complete**, not a merge authorization. Follow [CI lifecycle](../../rules/ci-workflow.md).
- **Stage 5:** requires specific authorization and a **verified, implemented typed** Course materializer accepting `CourseWorkflowMaterializerInput`. It creates deterministic **derived** human-readable `methodology.md` in stable heading order for Course/Module/Chapter; Markdown is never a second editable source. For each `kind: 'new'` placement, it creates a UUID-addressed **`index.ts satisfies LessonWorkflowStage1`** containing only reviewed identity, methodology and all four assessment decisions: **no `defineLesson`, Section drafts, `Not implemented` placeholders, Quiz/Flashcards selection IDs, or Lesson PR**. Those belong to separately authorized later Lesson production. The newly created Lesson's own derived `methodology.md` is produced only by its **later Lesson materializer**, not alongside the Course Stage 5 handoff. Child Questions/Flashcards also start as typed Stage 1 source handoffs rather than full banks. The parent integration [#775](https://github.com/KiT-Maverik/svitlo/pull/775) now contains a typed Stage 5 implementation and a separate manual-only `.github/workflows/course-typed-materialization.yml` gate, including pinned-source review and write authorization checks. **Neither is deployed on `develop` yet**, so the typed command cannot be used through default-branch Actions. The old YAML-only Course command and implementation have been removed from the integration tree by #796. Until the typed workflow reaches default `develop`, **Course Stage 5 cannot be dispatched**; never use the removed command as a fallback. New Lesson UUIDs/handoffs belong to Stage 5, never Stage 3. Every new/**existing** Lesson placement requires four independent `production.assessment` booleans: `questionBankRequired`, `flashcardBankRequired`, `quizSectionRequired`, `flashcardsSectionRequired`. Bank need is distinct from Section need; `quizRequiredForCompletion: true` separately implies a completed enabled Quiz Section. It does **not** start Lesson Production.
- **Stages 6–7:** authorized Course-owned translations and independent linguistic review occur in the **same entity PR** and do not certify independently authored Lessons. Follow [Translation Workflow](../translation-workflow/README.md).

## Seven stages

| Stage | Responsible role | Acceptance boundary |
| --- | --- | --- |
| 1. Create Course Methodology | Methodologist | Complete `CourseWorkflowStage1`: identity, pedagogy, verified target/prerequisite scope, evidence, `production.languages`, accessibility and standards |
| 2. Design Course Structure | Methodologist | `CourseWorkflowStage2`: ordered permitted hierarchy, substantive Module/Chapter editorial intent, verified Skill-only Lesson slots, Episode focus/purpose |
| 3. Design & Match Lessons | Methodologist + Assessment Architect | `CourseWorkflowStage3`: every Lesson slot resolved, with four independent bank/Section decisions and their rationale for both new and existing Lesson placements |
| 4. Review Course Plan | Independent Methodologist + Assessment Architect | Final corrected Stage 3 source reviewed in a separate context, findings/edits and source SHA recorded once in the Course PR |
| 5. Materialize Course | Coding Agent | Reviewed final typed input → derived methodology Markdown and new Lesson Stage 1 TS handoff only; no runnable Lesson or Lesson PR |
| 6. Translate Course | Technical Translator | Authored Course-local target locale fields, checked against actual language support |
| 7. Review Course Translations | Independent Technical Translator | Source-SHA-pinned semantic/linguistic approval for each required Course locale |

## Migration boundary

The obsolete Course-only YAML workflow, CLI, validator and manual Course editorial schema were removed in #796 at the owner's direction. The replacement typed workflow remains deployment-gated: until it is merged into default `develop` and validated in a real authorized run, **do not claim Stage 5 can execute**. Shared YAML schemas and other Lesson, Questions and Flashcards consumers are outside this Course cleanup.

For detailed methodology, partial/final acceptance, assessment-only Lesson dependencies, PR tracker format and Stage 5–7 handoffs, consult only [Create Course Flow](./create-course-flow.skill.md).
