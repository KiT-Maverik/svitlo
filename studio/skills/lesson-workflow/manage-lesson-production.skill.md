# Manage Lesson Production — historical Issue recovery

**New workflow:** [Create Lesson Flow](./create-lesson-flow.skill.md) replaces the mandatory Lesson Production Issue tracker with **one Draft Lesson PR per UUID**, whose body is the canonical workflow status/review evidence. Do **not** create another mandatory Issue or competing tracker for new work. Historical Issue bodies, comments and Git history remain recoverable; no new Production Issue Form is required; new entity-owned translation and independent review also remain in the same Lesson PR; historical translation Issues remain recoverable.

For an existing Lesson Production Issue, read the **entire current Issue**, comments, source/approval SHAs, bounded Lesson UUIDs and linked Course/Lesson PRs. Reconcile each UUID to its current source and existing PR; only create a new Draft Lesson PR if truly absent and authorized. Preserve independent review results, their exact source revisions, outstanding blockers and approval links and cross-reference the former Issue from the Lesson PR. Do not silently reassign UUIDs, overwrite content or delete Issue history.

Legacy `content.yaml`, `lesson.yaml` and `methodology.md` are historical provenance to reconcile non-destructively when separately migrating to the single staged Lesson `index.ts` (`LessonWorkflowStage1` then `LessonWorkflowStage2`). Historical Issue stages such as `generateSources` and `validation` do not equal the **ten** current Lesson stages, including distinct Stage 6.1/6.2/6.3 gates. The only reviewed Lesson source transition on #775 is `/lesson materialize typed` after default-branch deployment; the YAML Builder/Finalizer were removed. Do not write a competing checklist into a historical Issue or infer approval from a number, checkmark, generated review file or materializer run.
