# Create Lesson Content

**Persona:** [Educational Screenwriter](../../personas/educational-screenwriter.persona.md). **Coordinator:** [Create Lesson Flow](./create-lesson-flow.skill.md), Stage 2. Read Stage 1 `production.methodology`, actual Engine Lesson/Section/ContentBlock Config/Zod and renderer/UI Kit capabilities, current source and review history first. No new mandatory Issue, `content.yaml` or “Approved”-frontmatter gate.

Expand **the same temporary `lesson.yaml`** with stable Lesson, Section and Block UUIDs/slugs, real typed `items/order` collections and Config-shaped `config`/authoring-only `production` at nested nodes. Author substantive learner-facing **source-language** explanations, context, definitions, correct worked examples/counterexamples, practical teaching interactions, reflection, misconceptions, understandable feedback and natural transitions. Supply appropriate `production.purpose`/`pedagogicalIntent`, complete `production.specification`/`prompt`/`script`/`storyboard` and accessibility/offline/weak-device equivalents for relevant Scenes, media and Quest. Proposed features are not necessarily implemented UI.

Honor Methodologist Quiz intent without inventing full Question/Flashcard banks or grading, retain `config.params.languages` intent and only source `production.documentLanguage` locale values. Keep the Lesson independent of Course-only characters/story and avoid fabricated media IDs. No arbitrary block or Section quotas; passive one-line Sections need editorial justification. If `content.yaml` already exists as a reviewed legacy plan, explicitly migrate its full meaning and source/approval provenance, never silently overwrite or create a competing new source.

Record source SHA, node coverage, missing implementation specs and handoff to independent Content Review in Lesson PR. Full YAML validation is a Stage 6 technical boundary, not Stage 2 approval.
