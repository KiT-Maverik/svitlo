## Additional experience and assessment boundaries

2. **Current ContentBlock names:** `text`, `markdown`, `checkpoint`, `code`, `audio`, `video`, `youtube`, `image`, `carousel`, `scene`, `subtitles`. The new `subtitles` Build contract exists, but its UI renderer and technical YAML handoff are **not implemented**; record them as production dependencies. Do not use the obsolete `blockType` property or invent new supported types. For each block, record its editorial `key`, actual type, pedagogical purpose, source copy/structured spec, implementation `readiness`, and accessible alternative. Read current renderer and typed contracts to assess feasibility.

4. **Question ownership:** separately owned assessment briefs may specify intended evidence and cognitive operation, but must not invent the actual Question bank, correct responses, scoring, grading or mastery policy. The Assessment Architect produces validated items. Do not assume each cognitive operation corresponds to one Question type; the type is a UI interaction mechanism.

6. **Experience quality:** use prediction, visualization, exploration, useful feedback, worked examples, retrieval and transfer as appropriate. No compulsory theory/practice/quiz recipe; no decorative interaction quotas. Preserve accuracy, cognitive load, age suitability, inclusive keyboard/touch access, RTL, low-end/offline equivalence and meaningful non-visual alternatives. A `checkpoint` is a learning/reflection block, **not** scored Quiz evidence.

## Quest Section plans (Build contract exists; runtime pending)

A Quest is neither an ordinary ordered `blocks` Section nor a Quiz; see [Quest](../../docs/entities/quest.md). When the approved learning experience requires an isolated, stateful interactive workspace, the editorial `lesson.yaml` may describe `type: quest` with named Stage and Task proposals, including mandatory `start`, at least one Scene specification for each Task, all planned media/caption/accessibility production requirements and explicit branches determined by Scene actions. Never invent a `blocks` list or positional `order` inside Quest; record story-free learning flows in neutral Lessons and story missions in Episodes. This plan is _not_ a publishable Engine Quest: The YAML draft scaffolder and editor schema may support Quest, but the Lesson/Episode runtime Section union and UI remain pending. Maintain a specific nested `production` specification of the pending runtime dependency until implemented and independently validated.
