# Lesson Workflow

**Start at [Create Lesson Flow](./create-lesson-flow.skill.md)** for all new or resumed standalone/Course-originated Lessons. The canonical Skill requires an explicit eight-stage progress checklist, completed-stage declaration and one copyable next-action chat instruction at every handoff or PR-number resume. Status requests do not authorize execution; all eight completed stages must be declared explicitly, separate from QA/publication. One Draft Lesson PR tracks eight stages, an independent Stage 3 review and same-chat Stage 4–5 specialist audit SHAs; one temporary `lesson.yaml` holds ordered `config` + nested `production` through Stages 1–5. Historical Lesson Production Issues remain evidence but are no longer mandatory for new production. Questions/Flashcards are separate child workflows; substantive teaching Lessons normally own a Question Bank even when they have no Quiz. **Questions must be completed before Flashcards unless the _own_ bank is explicitly Not Applicable with verified Methodologist rationale.** A Course assessment-only Lesson can have no own bank but must resolve reviewed, integrated and published upstream banks before its Quiz selection and publication; an unfinished bank is never N/A. Translation campaigns use the Draft PR protocol for new work; historical Translation Production Issues retain their approved scopes and evidence.

**Bank Stage 5 CI handoff (after deployment to `main`):** Questions and Flashcards have separate, opt-in source-materialization commands on their **own child Draft PRs**: `/questions materialize` and `/flashcards materialize`. Both execute the actual create-only YAML → TS builders through the trusted [bank materialization workflow](../../../scripts/ci/bankMaterialization/README.md), commit only the corresponding new bank modules, and preserve `questions.yaml` / `flashcards.yaml`. Agents must verify the Actions run and generated commit, then continue the same bank Stage 5; neither command marks production complete. See [Create Questions Flow](./create-questions-flow.skill.md) and [Create Flashcards Flow](./create-flashcards-flow.skill.md) for reviewed YAML/PR checklist gates.

**Stage 6 source command:** after verifying deployed default-branch workflow, an authorized collaborator posts exact `/lesson materialize` on the existing Draft Lesson PR. See [Lesson Stage 6 command runbook](../../../scripts/ci/lessonMaterialization/README.md) for trusted resolve/analyze/publish, source preservation, Course child branch handling, SHA/run verification and the separately authorized `/lesson finalize`. Agents resuming with only a Lesson PR number must inspect stage/identity/evidence before recommending this command. The command is source handoff **within** Stage 6, never its completion or bank/media production.

**Independent-bank decision after Lesson source handoff:** as soon as Stage 6 has produced verified typed Lesson sources and current derived reference Markdown (even if bank-dependent Quiz links keep Stage 6 in progress), the parent Lesson status report recommends **Questions** first when an own bank is required, then **Flashcards** only after Questions are reviewed and integrated. An explicit Methodologist-supported `Questions: Not Applicable` permits justified Flashcards without a Question Bank; missing Questions or the absence of a Quiz does not. Neither bank is a ninth Lesson stage, and each child workflow now has its own seven-stage checklist and copyable next-action handoff.

Specialist operations:

1. [Create Lesson Brief](./create-lesson-brief.skill.md) — Methodologist Stage 1; reuse adequate existing Course/standalone methodology, create missing standalone methodology.
2. [Create Lesson Content](./create-lesson-content.skill.md) — Screenwriter Stage 2; full source-language learning Content in the same `lesson.yaml`.
3. [Review Lesson Content](./review-lesson-content.skill.md) — **the only new independent chat**: a Stage 3 Content Reviewer who did not author Stages 1–2, with direct, documented editorial fixes and source-SHA recheck.
4. [Review Lesson Experience](./review-lesson-experience.skill.md) — Stage 4 specialist audit and direct repairs **in that same chat**, with explicit Learning Experience Expert persona switch.
5. [Review Lesson Methodology](./review-lesson-methodology.skill.md) — Stage 5 specialist compliance and in-scope repairs **in that same chat**, with explicit Methodologist persona switch. Material Stage 1 scope changes still require owner authorization.
6. [Implement Scene](./implement-scene.skill.md) — Stage 6 specialist; [Finalize Lesson](../../../shared/engine/scripts/finalizeLesson/README.md) supports a strict `--preserve-config` first-time handoff; default strict finalize deletes unchanged YAML only after verified transfer.
7. [Create Lesson Questions](./create-lesson-questions.skill.md) (separate seven-stage [Create Questions Flow](./create-questions-flow.skill.md), [PR #647](https://github.com/KiT-Maverik/svitlo/pull/647)) and [Create Lesson Flashcards](./create-lesson-flashcards.skill.md) (separate seven-stage [PR #646](https://github.com/KiT-Maverik/svitlo/pull/646)) — child Draft PRs with strict Questions-first prerequisite, not main Lesson stages.
8. [Manage Lesson Production](./manage-lesson-production.skill.md) — legacy Issue evidence recovery/migration only.

**Stages are strictly forward-only: Stage 3 → Stage 4 → Stage 5 → Stage 6.** Each review fixes its own findings in the same chat and commits an attributable source SHA. Stage 4 consumes the **completed** Stage 3 content review; Stage 5 consumes **both** completed Stage 3 Content and Stage 4 Experience reviews and is the **final whole-Lesson methodology/content/experience acceptance gate**. Stage 5 must directly fix its methodology and consistency findings, verify the entire latest YAML, record the final source SHA and **hand off to Stage 6**, optionally in the same chat when authorized. **Do not reopen, uncheck, or request re-review of Stage 3/4 because Stage 5 corrected source**. Their exact prior review SHAs are preserved; Stage 5 owns final integrated acceptance. Only a genuine unapproved curriculum/assessment decision blocks Stage 5 and is resumed at Stage 5, never routed backwards. Other independent-bank and translation-review rules are unchanged.

Flashcards Flow includes an independent **Flashcards Section Design** stage: the Section selects a small, review-justified ordered UUID subset; the standalone bank is not embedded into Lesson Props. See [Create Flashcards Flow](./create-flashcards-flow.skill.md) for the complete seven-stage procedure and Questions-first gate.

Old `lesson-content.schema.json` and `lesson-methodology-frontmatter.schema.json` are read-only **legacy editorial input** contracts, not new Lesson authoring requirements. At Stage 6 only, validate completed `lesson.yaml` using the Engine-derived `lesson.scaffold.schema.json` + `production.schema.json`; draft stages may be structurally incomplete without artificial `draft` or `approved` flags. No new `content.yaml` or fabricated locales.
