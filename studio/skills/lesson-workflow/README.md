# Lesson Workflow

Each task is an **independent specialist skill**. The Lesson UUID directory is stable and Course-neutral; editors explicitly approve each role-owned artifact before downstream work. For an authorized new Lesson production scope, **locate or initialize one standard GitHub Issue for the entire frozen Lesson UUID set** before opening specialist PRs; reuse it through all stages and across chats. Do not create an Issue per Lesson or step. For Lessons identified by [Match Course TOC Lessons](../course-workflow/match-course-toc-lessons.skill.md), **resume the exact fixed-scope Issue handed off by Course Workflow**, including Course ID, matched slot keys, Methodologist Drafts and current approvals. Do not allocate replacement Lesson UUIDs, duplicate matching work, or confuse creation of an Issue with Methodology approval.

1. [Create Lesson Brief](./create-lesson-brief.skill.md) — **Methodologist Persona**. Creates `methodology.md` with pedagogical scope, verified Skill links, separate `documentLanguage` vs `supportedLanguages`, and an **explicit `assessmentPlan`**. This can declare zero, one or multiple pedagogically necessary Quizzes, each with verified Skill IDs and typed `AssessmentMethodKey` values. See [Methodology frontmatter schema](./lesson-methodology-frontmatter.schema.json). The [Course Lesson matcher](../course-workflow/match-course-toc-lessons.skill.md) reuses these same requirements when drafting missing Lessons.
2. [Create Lesson Content](./create-lesson-content.skill.md) — **Educational Screenwriter Persona**, after Methodology approval. Creates **`content.yaml`** — ordered, machine-readable Section/ContentBlock/Quiz plan with source-language learner copy, accessibility and implementation dependencies. See [Lesson Content schema](./lesson-content.schema.json). Optional `scenes/*.scene-spec.md` documents provide the independent source for bespoke Scene implementation.
3. [Review Lesson Experience](./review-lesson-experience.skill.md) — independent [Learning Experience Expert](../../personas/learning-experience-expert.persona.md). Checks educational effectiveness, interaction appropriateness, accessibility and production dependencies; records source-specific findings in the review PR/Issue, then its verified PR in Lesson `review.ts` once assembled Props can be checked.
4. [Review Lesson Methodology](./review-lesson-methodology.skill.md) — independent Methodologist. Confirms subject correctness, Skill/outcome/prerequisite coverage and Quiz/Assessment Method alignment; records source-specific findings in the review PR/Issue, then its verified PR in Lesson `review.ts` once assembled Props can be checked.
5. [Manage Lesson Production](./manage-lesson-production.skill.md) — GitHub coordinator for **one or multiple Lessons in one fixed-scope Issue**, using [the Issue Form](../../../.github/ISSUE_TEMPLATE/lesson-production.yml), per-Lesson status rows and cross-chat PR handoffs. An authorized specialist may process all ready Lessons in a batch; do not ask for "continue" after every Lesson.

6. [Create Lesson Questions](./create-lesson-questions.skill.md) — **Learning Assessment Architect Persona**, after approved Methodology and Screenwriter content/reviews. Writes one source-language, machine-readable `questions.yaml` bank per Lesson with exact assessment method/Skill mappings, type-specific answer models, evidence coverage and deliberate non-duplication. **Retains the full Question bank for future Custom Practice, but selects only an explicit, pedagogically justified subset for each ordinary Lesson Quiz** through `quizAssignments[].selection`; the technical handoff must deliberately map this selection into the matching Quiz Section Config parameters without modifying Screenwriter-owned `content.yaml`; the generic draft scaffolder does not make editorial decisions. See [Lesson Questions schema](./lesson-questions.schema.json). This is a distinct specialist production stage, **not automatically launched** by prior approval.
7. [Create Flashcards Flow](./create-flashcards-flow.skill.md) — independent six-stage, PR-tracked Flashcards workflow, by Lesson UUID or Lesson PR, with Lesson Markdown reference (#645), approved full Question bank or verified Methodologist `Not Applicable`, source-language Engine-shaped YAML, independent review, typed source scaffolding, production, translation and linguistic review. [Detailed Flashcard design rules](./create-lesson-flashcards.skill.md) remain mandatory. This stage is independent of Scene coding.
8. [Project editorial plans into one technical `lesson.yaml`](../../docs/architecture/yaml-config-scaffolding.md) — **technical handoff after source-specific editorial approvals**. Each Lesson/Section/ContentBlock node has `config` (Engine fields and single ID) plus optional `production` (authoring-only specification), under the current generated scaffold JSON Schema. The Lesson-only [Lesson Builder](../../docs/architecture/lesson-yaml-builder.md) emits incomplete nested `define*` TS and requested ID-addressed specs. **TypeScript errors from pending resources are by design**; the scaffolder does not approve content, typecheck, publish Props, generate assets, or translate.
9. [Implement Scene](./implement-scene.skill.md) — **Coding Agent Persona**, after approved Scene specifications and applicable source scaffolding. Implements Scene behavior, source-language-only typed text, tests and lazy registry integration, without implementing the YAML Builder.
10. **Other subsequent stages, not automatically launched:** Media Production, Translation Production and publication; these depend on resolved requirements and independent approvals.

## Language and generation boundary

The canonical Screenwriter, Assessment Architect and Flashcard YAML plans each have **one** `documentLanguage`, included in the planned `supportedLanguages`. The technical `lesson.yaml` uses `config.params.languages` for intended coverage but populates ordinary learner-facing `locale` fields **only** for the chosen source language; `documentLanguage` belongs to the root `production` authoring section, not Engine `config`. Other translations are intentionally absent. The draft scaffolder must not fabricate values or guarantee that TypeScript compiles. Typecheck, complete locale coverage, editorial sign-off, `generateLessonProps`, and publication are **separate subsequent gates**. See [Engine YAML authoring handoff](../../docs/architecture/yaml-config-scaffolding.md).

Existing `content.md` files are legacy editorial materials. Do not duplicate competing canonical content sources or migrate them without explicit approval. `methodologist-brief.md` is the legacy Methodology filename and is retained in place when revising an existing Lesson.

## Approval and group-production handoffs

Review PRs are independent, source-revision-specific recommendations: a reviewer `pass` does not automatically give editorial approval. The canonical persistent Lesson review register is the Lesson-root `review.ts` (typed `LessonReview`) once implemented, not new `*-review.md` files. Until a compiled Props revision exists, keep exact editorial source SHA, verdict and sign-off evidence in the existing PR and production Issue; reconcile this evidence before writing the corresponding PR into `review.ts`. A local linguistic or review decision belongs in a short TypeScript comment immediately above its recorded PR; global decisions belong in Studio rules. The Screenwriter revises `content.yaml` for accepted changes; affected reviews must be repeated against the new source. [Lesson Production lifecycle](../../docs/architecture/lesson-production-workflow.md) defines the per-Lesson approval and status model, while the GitHub Issue holds the batch's persistent cross-agent coordination. The Question bank and Flashcard YAML require **separate editorial sign-offs for their exact source revisions** before generation. A later material change to approved Questions requires rechecking dependent Flashcards and generated references. The Issue can contain many Lessons; do not create a new Issue or PR for every short step by default.

## Code-visible unfinished Scene work

Source `TODO(scene/asset/i18n/a11y/test)` comments remain beside real unresolved implementation paths and link the Lesson Production Issue. Remove each TODO in the fix that genuinely resolves and verifies it; do not drop unresolved blockers to claim completion. See [Implement Scene](./implement-scene.skill.md).

## Flashcard authoring — downstream of the approved Question bank

[Create Lesson Flashcards](./create-lesson-flashcards.skill.md) — **[Flashcard Learning Architect](../../personas/flashcard-learning-architect.persona.md)**. This is a separate, subsequently authorized authoring stage and a **hard downstream dependency** of the approved full Question bank produced by [Create Lesson Questions](./create-lesson-questions.skill.md). The *only* exception is an explicitly verified `Questions = Not Applicable` decision with Methodologist rationale in the owning Lesson PR. Missing or unapproved Questions and a Lesson without a built-in Quiz do not qualify. If Question TypeScript exports are not ready, author approved YAML references but block their generated TS imports until the real exports exist.

It writes exactly one source-language `flashcards.yaml` per Lesson, using Engine's `yamlFlashcard_Schema` (and the [named scaffolder](../../../shared/engine/scripts/flashcardBuilder/README.md)), with brief front/back/hint ContentBlocks, **typed list/warning/acronym/custom flags**, named TextBlock variables, mnemonic-construction metadata inside the acronym flag, Question-field references, and **nine canonical Flashcard relation types, authored once and mirrored onto both endpoint cards with actual IDs**. Runtime flags are discriminated objects, and UI Kit automatically maps them to localized MUI Chips (custom value, color and optional safe icon). Future generation must import matching Question objects rather than duplicating their localized fields; translations of locale-dependent custom labels and acronyms are still required. Typed relations and the Engine link materializer are already implemented; UI graph navigation/scheduling remains future work.
