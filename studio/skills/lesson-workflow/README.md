# Lesson Workflow

**Canonical authority:** [Create Lesson Flow](./create-lesson-flow.skill.md), root [AGENTS.md](../../../AGENTS.md), [Lesson](../../docs/entities/lesson.md) and the actual Engine [Lesson workflow types](../../../shared/engine/types/workflow/lessonWorkflow.types.ts). Use one existing Lesson-owned **Draft PR and branch** per UUID. The PR description holds the stage checklist, source SHA and independent review evidence; it is never duplicated in TypeScript, YAML, an Issue or another tracker.

## One progressive TypeScript source, ten stages

1. **Methodology — Methodologist.** Export one `draft.ts` planning object at the Lesson UUID root using `satisfies LessonWorkflowStage1`. When Course-originated, assess the Course-owned seed, preserve its allocated UUID and placement and reuse its reviewed methodology and language/assessment intent; otherwise author from any authorized standalone input. The four bank/Section assessment choices are mandatory editorial booleans, distinct from `quizRequiredForCompletion`. No Sections, Blocks, Questions, Flashcards or `defineLesson`.
2. **Content Creation — Educational Screenwriter.** Extend that **same** object into `satisfies LessonWorkflowStage2`, including stable, ordered Section and ContentBlock `{config,production?}` nodes, actual source-language teaching, Scene/media/Quest specifications and no fabricated translations or bank UUIDs. It is **plain typed authoring**, not nested Configurators.
3. **Content Review — independent editorial reviewer in a new chat.** Review the Stage 2 source at a pinned SHA, record findings and directly fix approved-scope defects **in that same object and Lesson PR**. No Stage 3 type, extra authoring document or separate PR.
4. **Experience Review — Learning Experience Expert.** Continue in the Stage 3 review chat under the correct specialist role, inspect all Sections and resource specifications, directly correct in-scope issues and record final Stage 4 source SHA. Do not reopen Stage 3.
5. **Methodology Compliance — Methodologist.** Final integrated whole-Lesson review/correction in the **same Stage 3/4 chat**, with final SHA and decisions. The reviewed Stage 2 object must `satisfies LessonWorkflowMaterializerInput` (alias of Stage 2); the compiler is not itself approval. No backward review loop.
6. **Resource Production — Coding Agent.** 6.1 separately authorized trusted **typed source materialization** using Lesson/Section/Block materializers ; atomically consume `draft.ts`, create `index.ts` and derive human-readable `methodology.md` and real modular `defineLesson` source, respecting create-only/no-clobber/UUID safety. Required Quiz/Flashcards Sections must already be **authored and enabled**; The Lesson materializer rejects a missing/disabled required Section **before emitting files**. Existing enabled but incomplete assessment Sections can produce nonpublishable blocked drafts until the independently reviewed banks supply real IDs and parameters. Source readiness and actual bank dependencies are separate release gates. 6.2 complete and strictly typecheck real generated sources/media/offline/a11y. 6.3 implement, register and test **every** required Scene, or record verified zero-Scene N/A. Never equate a source stub with Stage 6 success.
7. **Questions — independently owned seven-stage child workflow.** Only after authorized reviewed Lesson source and derived reference Markdown, create/resume the **Questions Stage 1 typed `draft.ts` handoff** in the actual Lesson-owned bank folder; never manufacture bank members or full Configurators. Check parent Stage 7 only after actual reviewed/integrated child completion, or documented Methodologist own-bank N/A, regardless of Quiz Section presence.
8. **Flashcards — independently owned seven-stage child workflow.** Questions-first or verified Questions N/A. Same minimal typed Stage 1 `draft.ts` handoff, independent seven-stage production/review/integration or justified N/A. A Flashcard Bank and Flashcards Section are distinct decisions.
9. **Translation.** Translate the **real materialized typed source**, locale dictionaries, Markdown/Code, media captions and Scenes for the planned locales **in this Lesson PR**. No separate translation PR/Issue or parallel YAML authoring.
10. **Translation Review.** Independent review in a different context using verified source-SHA/scope-pinned reference materials, on the **same Lesson PR**. Reviewer corrections and evidence stay there; actual full-locale publication is a separate technical/QA requirement.

Stages 3→4→5 are strictly forward-only: role-owned corrections at each stage update the same object, retain prior stage evidence at the SHA actually reviewed, and Stage 5 accepts the latest whole Lesson. The Lesson PR, not a Stage 3/4/5 type or status field, records review results. Stage 6.1/6.2/6.3 each have their own acceptance evidence; completion of one does not imply the others.

## Course, banks and implementation boundaries

For each new Lesson, Course Stage 5 emits a UUID-addressed `draft.ts satisfies CourseWorkflowLessonSeed` with `config`, `proposal` and `languageContext`, retaining the reviewed new-Lesson intent and source/planned languages. It neither completes independent Lesson Stage 1 nor generates Sections or bank IDs. See the [Course seed contract](../../../shared/engine/types/workflow/courseWorkflow.types.ts) and [seed materializer](../../../shared/engine/generators/materializers/course/lessonDraft.mjs). Initial Questions/Flashcards bank `draft.ts` files are separate independently authorized seven-stage handoffs. Bank ownership must not be conflated with Quiz/Flashcards Section presence. An assessment-only Lesson may select verified upstream Questions without creating an unnecessary duplicate own bank, but missing external references block publication.

The authorized Methodologist completes the independent Lesson Stage 1 object at the same canonical path, preserving the allocated UUID and actual Course placement/PR relationships when present. Standalone authoring requires neither Course ancestry, a parent PR, an automatic conversion nor an additional mandatory handoff. The Stage 1/2 contract, trusted Stage 6.1 typed orchestrator and separate authorization/source/HEAD/no-clobber gates are defined in the current Engine contracts and trusted workflow. Editorial reviews are tracked for coordination but never parsed by the Lesson materializer. The **only** Lesson PR command is `/lesson materialize` after the trusted workflow is deployed on default `develop`; see [trusted typed Stage 6.1](../../../scripts/ci/lessonMaterialization/README.md). The retired `/lesson finalize` and YAML Builder are not compatible fallbacks. Draft CI, local tests and source materialization do not establish successful default-branch invocation, full typechecks, independent reviews or release readiness.

Historical `lesson.yaml`, `content.yaml`, `methodology.md` and their review/provenance records are **migration evidence only**, not supported alternative authoring inputs. Historical files are not executable production inputs. Preserve historic authored files non-destructively pending separate owner-authorized migration. Read [Lesson Content](../../docs/entities/lesson-content.md) for historical artifact interpretation and [Section](../../docs/entities/section.md) for the actual Engine Section/runtime boundaries. PR lifecycle follows [CI workflow rules](../../rules/ci-workflow.md): keep Draft during active work and when unresolved work remains; once the specifically authorized deliverable is complete and fit for inspection, mark Ready for review without another prompt and verify current-head target checks. **Ready is not approval to merge**, publish or start another entity workflow.
