# Lesson Workflow

**Start at [Create Lesson Flow](./create-lesson-flow.skill.md)** for all new or resumed standalone/Course-originated Lessons. The canonical parent Lesson Workflow now has **ten stages**: editorial Stages 1–5, Stage 6 source preparation with **three individually checked substeps (6.1–6.3)**, Stage 7 Questions, Stage 8 Flashcards, Stage 9 Translation and Stage 10 Translation Review. Questions/Flashcards remain independently authored in their own **seven-stage child Draft PRs**; their parent Lesson checkboxes record verified child completion/integration or Methodologist-backed N/A, never bank content embedded in Lesson Config. One Draft Lesson PR is the sole parent tracker; Stage 3 has one independent review and Stage 4–5 specialist audits continue in that chat. Historical Issues remain evidence, not mandatory new trackers.

Stages 7/8 require source and derived reference Markdown from Stage 6. A substantive instructional Lesson normally owns Questions even without an in-Lesson Quiz; Questions are completed/reviewed/integrated before Flashcards, unless the own bank is explicitly N/A with Methodologist rationale. Assessment-only Lessons may use verified upstream Question Banks with their exact ownership and locale dependencies. Existing eight-stage Lesson PR descriptions are migrated **in place**, preserving old stage evidence and renumbering only the old translation checkboxes as 9/10.

**Bank Stage 5 CI handoff (after deployment to `main`):** Questions and Flashcards have separate, opt-in source-materialization commands on their **own child Draft PRs**: `/questions materialize` and `/flashcards materialize`. Both execute the actual create-only YAML → TS builders through the trusted [bank materialization workflow](../../../scripts/ci/bankMaterialization/README.md), commit only the corresponding new bank modules, and preserve `questions.yaml` / `flashcards.yaml`. Agents must verify the Actions run and generated commit, then continue the same bank Stage 5; neither command marks production complete. See [Create Questions Flow](./create-questions-flow.skill.md) and [Create Flashcards Flow](./create-flashcards-flow.skill.md) for reviewed YAML/PR checklist gates.

**Stage 6 source command:** when deployed to the default branch `develop`, authorized collaborators use exact `/lesson materialize` on the existing Draft Lesson PR. See [Stage 6 command runbook](../../../scripts/ci/lessonMaterialization/README.md); an authorized `/lesson finalize` can subsequently delete only the verified unchanged `lesson.yaml`. Verify Actions run, pinned YAML source, generated commit and preserved source. The command can complete **6.1 only**; 6.2 accessibility and 6.3 offline each require their own evidence. After all three are verified, check Stage 6 and hand off directly to Stage 7 Questions; schema/preflight, Builder fidelity, typed source and scoped tests remain automated CI/final-QA duties, not a fourth agent substep. Scenes/media creation is **not Stage 6**: record each missing physical asset as a separate human/specialist-owned resource blocker for final QA/Ready.

**Stage 7/8 bank handoff:** directly after completed 6.1–6.3 and Stage 6, recommend a Questions child-PR start/resume command for the exact parent Lesson. Once reviewed/integrated (or genuinely own-bank N/A), recommend Flashcards if justified or record N/A. Offer one copyable chat command, usable in the same or a new chat, but never create child PRs automatically. The parent tracks Stages 7 and 8 with independent child PR/review/integration evidence. Translation follows at Stages 9/10.

Specialist operations:

1. [Create Lesson Brief](./create-lesson-brief.skill.md) — parent Stage 1 Methodology.
2. [Create Lesson Content](./create-lesson-content.skill.md) — parent Stage 2 Screenwriter content.
3. [Review Lesson Content](./review-lesson-content.skill.md) — parent Stage 3 independent Content Review (new chat).
4. [Review Lesson Experience](./review-lesson-experience.skill.md) — parent Stage 4 Learning Experience Expert (same chat).
5. [Review Lesson Methodology](./review-lesson-methodology.skill.md) — parent Stage 5 Methodologist (same chat).
6. [Finalize Lesson](../../../shared/engine/scripts/finalizeLesson/README.md) — parent Stage 6 source materialization/validation; not physical media production.
7. [Create Lesson Questions](./create-lesson-questions.skill.md) and [Create Questions Flow](./create-questions-flow.skill.md) — parent Stage 7 with separate seven-stage Questions child PR.
8. [Create Lesson Flashcards](./create-lesson-flashcards.skill.md) and [Create Flashcards Flow](./create-flashcards-flow.skill.md) — parent Stage 8 with separate seven-stage Flashcards child PR.
9. [Implement Scene](./implement-scene.skill.md) — independently authorized specialist physical resource blocker, **outside Stage 6**.
10. [Manage Lesson Production](./manage-lesson-production.skill.md) — legacy Issue evidence recovery only.

**Stages are strictly forward-only: Stage 3 → Stage 4 → Stage 5 → Stage 6.** Each review fixes its own findings in the same chat and commits an attributable source SHA. Stage 4 consumes the **completed** Stage 3 content review; Stage 5 consumes **both** completed Stage 3 Content and Stage 4 Experience reviews and is the **final whole-Lesson methodology/content/experience acceptance gate**. Stage 5 must directly fix its methodology and consistency findings, verify the entire latest YAML, record the final source SHA and **hand off to Stage 6**, optionally in the same chat when authorized. **Do not reopen, uncheck, or request re-review of Stage 3/4 because Stage 5 corrected source**. Their exact prior review SHAs are preserved; Stage 5 owns final integrated acceptance. Only a genuine unapproved curriculum/assessment decision blocks Stage 5 and is resumed at Stage 5, never routed backwards. Other independent-bank and translation-review rules are unchanged.

Flashcards Flow includes an independent **Flashcards Section Design** stage: the Section selects a small, review-justified ordered UUID subset; the standalone bank is not embedded into Lesson Props. See [Create Flashcards Flow](./create-flashcards-flow.skill.md) for the complete seven-stage procedure and Questions-first gate.

Old `lesson-content.schema.json` and `lesson-methodology-frontmatter.schema.json` are read-only **legacy editorial input** contracts, not new Lesson authoring requirements. At Stage 6 only, validate completed `lesson.yaml` using the Engine-derived `lesson.scaffold.schema.json` + `production.schema.json`; draft stages may be structurally incomplete without artificial `draft` or `approved` flags. No new `content.yaml` or fabricated locales.
