# Lesson Workflow

**Start at [Create Lesson Flow](./create-lesson-flow.skill.md)** for all new or resumed standalone/Course-originated Lessons. The canonical parent Lesson Workflow now has **ten stages**: editorial Stages 1–5, Stage 6 resource production with **three individually checked substeps: 6.1 source materialization, 6.2 typed resource completion, and 6.3 implemented/registered Scenes**, Stage 7 Questions, Stage 8 Flashcards, Stage 9 Translation and Stage 10 Translation Review. Questions/Flashcards remain independently authored in their own **seven-stage child Draft PRs**; their parent Lesson checkboxes record verified child completion/integration or Methodologist-backed N/A, never bank content embedded in Lesson Config. One Draft Lesson PR is the sole parent tracker; Stage 3 has one independent review and Stage 4–5 specialist audits continue in that chat. Historical Issues remain evidence, not mandatory new trackers.

Stages 7/8 require source and derived reference Markdown from Stage 6. A substantive instructional Lesson normally owns Questions even without an in-Lesson Quiz; Questions are completed/reviewed/integrated before Flashcards, unless the own bank is explicitly N/A with Methodologist rationale. Assessment-only Lessons may use verified upstream Question Banks with their exact ownership and locale dependencies. Existing eight-stage Lesson PR descriptions are migrated **in place**, preserving old stage evidence and renumbering only the old translation checkboxes as 9/10.

**Legacy YAML bank Stage 5 CI handoff (for existing YAML sources only, pending #775 migration):** Questions and Flashcards have separate, opt-in source-materialization commands on their **own child Draft PRs**: `/questions materialize` and `/flashcards materialize`. Both execute the actual create-only YAML → TS builders through the trusted [bank materialization workflow](../../../scripts/ci/bankMaterialization/README.md), commit only the corresponding new bank modules, and preserve `questions.yaml` / `flashcards.yaml`. Agents must verify the Actions run and generated commit, then continue the same bank Stage 5; neither command marks production complete. See [Create Questions Flow](./create-questions-flow.skill.md) and [Create Flashcards Flow](./create-flashcards-flow.skill.md) for reviewed YAML/PR checklist gates.

**Stage 6 execution:** authorized collaborators use exact `/lesson materialize` on the existing Draft Lesson PR for **6.1 only**; see the [trusted command runbook](../../../scripts/ci/lessonMaterialization/README.md). After verifying the Actions run, source/commit SHA and generated inventory, **6.2** completes generated Lesson/Section/Block sources, real required resource references and strict TypeScript under the owning compiler (source-level accessibility/offline audits included); it is not a rubber-stamp of the generator. **6.3** implements and integrates every reviewed React Scene via [Implement Scene](./implement-scene.skill.md), including real components, registry, component tests and source-locale a11y/offline behavior; verified zero-Scene Lessons record an explicit N/A. The optional [Scene scaffolder](../../../shared/engine/scripts/sceneScaffolding/README.md) creates only drafts and requires a Scene-capable textbook. Stage 6 cannot be checked while required Scenes are merely `defineScene`/`specification.md` or while required assets are fake/missing. Real locale translation/review belongs to Stages 9–10, independent bank work to 7–8, and complete publication/runtime QA remains later. Only an independently authorized `/lesson finalize` may safely retire the unchanged original `lesson.yaml` after verified transfer **and after any required Stage 6.3 Scene scaffolding has read its specifications**.

**Typed Questions Stage 7 handoff:** For the typed Questions workflow (#783), an authorized Lesson Stage 7 creates only a bank-owned `questions/index.ts` satisfying `QuestionBankWorkflowStage1`, using the verified Lesson UUID. That same file gains complete `QuestionBankWorkflowStage2` Questions and `QuestionBankWorkflowStage3` Quiz intent, is corrected by an independent reviewer, and needs an explicit safe Stage 5 transition into canonical modules after #775 integrates the nine #780 materializers. No second bank UUID, YAML or duplicate selection ledger is created. The old bank CI commands below remain **YAML-only** and must not be used on this typed file.

**Stage 7/8 bank handoff:** directly after completed 6.1–6.3 and Stage 6, recommend a Questions child-PR start/resume command for the exact parent Lesson. Once reviewed/integrated (or genuinely own-bank N/A), recommend Flashcards if justified or record N/A. Offer one copyable chat command, usable in the same or a new chat, but never create child PRs automatically. The parent tracks Stages 7 and 8 with independent child PR/review/integration evidence. Translation follows at Stages 9/10.

Specialist operations:

1. [Create Lesson Brief](./create-lesson-brief.skill.md) — parent Stage 1 Methodology.
2. [Create Lesson Content](./create-lesson-content.skill.md) — parent Stage 2 Screenwriter content.
3. [Review Lesson Content](./review-lesson-content.skill.md) — parent Stage 3 independent Content Review (new chat).
4. [Review Lesson Experience](./review-lesson-experience.skill.md) — parent Stage 4 Learning Experience Expert (same chat).
5. [Review Lesson Methodology](./review-lesson-methodology.skill.md) — parent Stage 5 Methodologist (same chat).
6. [Finalize Lesson](../../../shared/engine/scripts/finalizeLesson/README.md) — Stage 6.1 source materialization; Stage 6.2 completes strictly typed Lesson resources and required media, Stage 6.3 implements Scenes.
7. [Create Lesson Questions](./create-lesson-questions.skill.md) and [Create Questions Flow](./create-questions-flow.skill.md) — parent Stage 7 with separate seven-stage Questions child PR.
8. [Create Lesson Flashcards](./create-lesson-flashcards.skill.md) and [Create Flashcards Flow](./create-flashcards-flow.skill.md) — parent Stage 8 with separate seven-stage Flashcards child PR.
9. [Implement Scene](./implement-scene.skill.md) — mandatory **Stage 6.3** for a Lesson with Scenes, with optional separate child PR ownership but required integration and tests before Stage 6 completion.
10. [Manage Lesson Production](./manage-lesson-production.skill.md) — legacy Issue evidence recovery only.

**Stages are strictly forward-only: Stage 3 → Stage 4 → Stage 5 → Stage 6.** Each review fixes its own findings in the same chat and commits an attributable source SHA. Stage 4 consumes the **completed** Stage 3 content review; Stage 5 consumes **both** completed Stage 3 Content and Stage 4 Experience reviews and is the **final whole-Lesson methodology/content/experience acceptance gate**. Stage 5 must directly fix its methodology and consistency findings, verify the entire latest YAML, record the final source SHA and **hand off to Stage 6**, optionally in the same chat when authorized. **Do not reopen, uncheck, or request re-review of Stage 3/4 because Stage 5 corrected source**. Their exact prior review SHAs are preserved; Stage 5 owns final integrated acceptance. Only a genuine unapproved curriculum/assessment decision blocks Stage 5 and is resumed at Stage 5, never routed backwards. Other independent-bank and translation-review rules are unchanged.

Flashcards Flow includes an independent **Flashcards Section Design** stage: the Section selects a small, review-justified ordered UUID subset; the standalone bank is not embedded into Lesson Props. See [Create Flashcards Flow](./create-flashcards-flow.skill.md) for the complete seven-stage procedure and Questions-first gate.

Old `lesson-content.schema.json` and `lesson-methodology-frontmatter.schema.json` are read-only **legacy editorial input** contracts, not new Lesson authoring requirements. At Stage 6 only, validate completed `lesson.yaml` using the Engine-derived `lesson.scaffold.schema.json` + `production.schema.json`; draft stages may be structurally incomplete without artificial `draft` or `approved` flags. No new `content.yaml` or fabricated locales.

**Across Course/Lesson/Questions/Flashcards:** early incomplete authoring sources are reviewed by its content specialists, not forced through redundant stage-specific technical schema commands. Their authoritative builder/materializer validates at the actual production boundary before writing. For Questions, use the staged TypeScript types and the explicit post-review source transition once integrated; never claim legacy YAML tooling implements this typed authoring. See [validation boundary audit](../../docs/architecture/yaml-config-scaffolding.md#validation-boundaries-across-the-four-entity-workflows).
