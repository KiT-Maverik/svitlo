# Manage Translation Production — entity-owned PR workflow

**For new Course, Lesson, Questions and Flashcards production, translation and independent Review Translation happen in their existing entity-owned PR.** This Skill works with [Technical Translation](./technical-translation.skill.md), [Review Translation](./review-translation.skill.md), [Technical Translator Persona](../../personas/technical-translator.persona.md), the appropriate entity flow, repository/GitHub conventions and real typed contracts. A translation campaign is a **phase of the entity**, not another GitHub project.

Do **not** open a separate translation integration PR, translator subtask PR, reviewer PR, branch, Translation Production Issue, or competing status file to complete those entity flows. This policy **does not** remove the independent Questions and Flashcards _entity PRs themselves_, and does not retroactively close or rebase historical translation campaigns. Any unrelated Skills taxonomy/UI Kit campaigns should follow their separately applicable instructions until their topology is explicitly changed.

## Existing work and historical Issue/PR recovery

Before acting, identify the real entity PR, head/base branch, immutable UUID and current review/source SHAs. Read its body and comments, existing child bank PRs, historical translation PR/Issue links and active assignments. Reuse the entity PR for **new** locale work. An ongoing historical Issue/translation PR remains valid evidence and retains its owner permissions and commitments. Do not mass-close, rewrite, re-scope or force-migrate historical work: first obtain owner authorization, inventory the existing assignments/source/review SHAs, copy reconciled evidence, and preserve links under [legacy recovery](./legacy-production-issues.md). General GitHub Issues and trusted `issue_comment` commands are unaffected.

## One exact entity × locale scope in the existing PR

1. Identify the Course UUID, Lesson UUID, or owning Lesson UUID plus Questions/Flashcards bank type; record the exact source-language revision and supported target-language set. Keep the **existing entity PR and branch ancestry**; neither a separate translation PR nor another status YAML is created.
2. Inventory every learner-facing field for the selected entity and every required locale as an ordered **entity/child UUID × locale × canonical source path/field** matrix. Exclude immutable IDs, methodology-only prose and content owned by an independent entity; for a Course, embedded Lesson references do not transfer ownership of standalone Lesson translations. Report present/missing/blocked fields and an exact source SHA.
3. If independent translators contribute, give them non-overlapping entities/locale/file ownership **on the same PR branch**. Do not perform concurrent writes to a shared file; sequence contributions and reconcile current HEAD before each write. Assignments are coordination notes, not extra PRs.
4. Translate only canonical typed localized fields via [Technical Translation](./technical-translation.skill.md). Never edit derived Markdown, forge a translated locale, weaken TypeScript or change immutable or nonlocalizable fields. Record the author, affected paths/locales and commit in the **existing entity PR**.
5. The owner explicitly authorizes **independent review** of a named entity/locale scope, source SHA and qualified reviewer. The reviewer must be distinct from the translator and work in an independent context/persona; a distinct Git branch/PR is neither required nor permitted solely for Review Translation.

## Same-PR independent linguistic review

- Generate the _bounded_ Code-derived Markdown and versioned manifest on the **existing entity PR branch** using [Agent CI Artifacts](../../../.github/workflows/agent-ci-artifacts.yml) or the documented local equivalent. For Course use a requested Course UUID and locale; for Lesson use one Lesson UUID and locale; for Questions use its owning Lesson UUID and Question-bank locale. For Flashcards, use the [scoped Flashcard Bank reference adapter](../../../shared/engine/scripts/generateFlashcardReviewArtifacts/README.md) and verify that it actually covers **the complete bank**, not merely Lesson Quiz selections. The trusted GitHub workflow must contain the adapter on its default branch to accept the slash command; until then use an authorized local read-only run or report that activation prerequisite, never invent a generated manifest.
- Pin `manifest.sourceCommit`, requested entity/locale, full document count, generated paths, `missing`/failures and `reviewReady`; confirm the output matches the exact reviewed revision and contains the relevant learner-facing content, scientific terms, accessible descriptions and canonical source links. A failed or missing selected document blocks that scope. Generated Markdown is **reference only**, never the source of truth.
- The independent reviewer reads **all requested content**, not only the diff, checks semantic/scientific fidelity, grammar, terminology, source-language consistency, age/accessibility, placeholders, Math/RTL where relevant and available media descriptions; record findings and evidence **in the same entity PR**. `reviewReady: true`, green TS and present locale keys are **not linguistic approval**.
- Review begins read-only. If permitted by the owner, the reviewer may use [Technical Translation](./technical-translation.skill.md) to correct **only** specified localized source fields directly on the same entity PR branch. Record the pre-fix reviewed SHA, fixed commit, paths and exact findings addressed. Rebuild scoped Markdown at the new source SHA and re-review all affected scope; do not invalidate unaffected reviewed languages.
- For each locale record translator identity/source SHA, reviewer identity/independent context, original reviewed SHA, findings/fixes, corrected reviewed SHA, authorization/decision and remaining blockers in the entity PR's existing stage tracker and comments. Populate only genuinely supported `review.ts` fields, with verified PR-number evidence where its Engine type permits. A numeric PR alone is **not** a signature or proof of independence, and multiple locales may correctly refer to the same entity PR number. Do not invent review fields or parallel Markdown reports.
- Run scoped technical checks and authoring/publication checks for the final changed source. Before Ready/merge, use `/agent-artifacts cleanup` on the **same entity PR**, verify no `.agent-ci-artifacts/` files remain in its diff, and meet its true production/locale/asset/accessibility gates. The owner's Ready/merge permission is separate from translation or linguistic-review authorization.

## Resumption and completion

On a request to continue an entity PR, reconcile its latest HEAD, source and manifest SHAs, stage checklist, source inventory, locale completion matrix, authorized reviewer/fixes and actual CI; resume the first authorized unfinished scope. A new source revision invalidates only the evidence derived from changed localized content or meaning. Distinguish `planned`, `in-progress`, `translated`, `review-in-progress`, `reviewed`, `blocked` and `complete`; never mark a language reviewed merely because a manifest exists or a reviewer was assigned.

**Complete** means every in-scope locale has genuine translations, independent qualified review at its current relevant source SHA, resolved findings, cleaned artifacts, and verified type/build/reference/production checks. Preserve historical approvals and provenance. No entity PR is merged, retargeted, or marked Ready as a side effect of a translator/reviewer reporting completion.
