# Translation Workflow

**Entity-owned translation/review:** For new Course, Lesson, Questions and Flashcards production, the **existing entity PR** owns translation, a separately performed independent linguistic review, locale-by-locale evidence and exact source/review SHAs. Translate, review and fix authorized locale fields on that **same branch**, without a new translation integration PR, translator/reviewer subtask PR, branch or Production Issue. The owner controls review start, exact source SHA, corrections, Ready and merge. The independent reviewer must be a different agent/context, not a different PR. The four entity workflow Skills own the stage checklist and handoff.

**Other localization campaigns:** [Manage Translation Production](./manage-translation-production.skill.md) defines a separate Draft integration/subtask topology only for explicitly authorized **non-entity** campaigns (for example, taxonomy or UI Kit batches). Preserve previously active Issues/PRs and their review evidence under [legacy recovery](./legacy-production-issues.md); do not silently migrate, close or retarget them. Neither an all-translators-merged baseline nor a new Issue is required for entity review.

**Persona:** [Technical Translator](../../personas/technical-translator.persona.md), for linguistic judgment across supported languages.

- **[Manage Translation Production](./manage-translation-production.skill.md):** coordinate separately authorized non-entity campaigns; it does not create additional PRs for entity-owned translation/review. Missing scoped reference Markdown blocks the affected review, not unrelated batches.
- **[Review Translation](./review-translation.skill.md):** independently inspect complete Code-derived Markdown for the requested entity family, textbook and locale, generated on the **existing entity PR** (or an authorized non-entity campaign's working PR); verify manifest/run/source SHA/scope, record findings and authorized fixes in that PR, with no report commits.
- **[Technical Translation](./technical-translation.skill.md):** implementation of actual localized text changes in canonical typed files in the entity PR, with the applicable TypeScript and source validation.
- **Standalone static-document translation:** not yet a published skill; propose it separately if needed. The active Technical Translation workflow covers typed localized source, not unapproved general document translation.

Reusable agent report workflow: [Agent CI Artifacts](../../../.github/workflows/agent-ci-artifacts.yml). An authorized `/agent-artifacts generate` command creates a one-day, SHA-pinned ZIP attached to the actual Actions run. Agents must list, download and inspect that run's artifact and `manifest.json`. New reports never commit to the working PR and have no cleanup command. The standalone `Agent CI Artifacts / clean` workflow has been deleted. Historical PRs with tracked report files must remove them via explicit normal commits; an owner must remove the deleted required status from protected-branch rulesets before merging. See [run-scoped report protocol](../../docs/architecture/agent-ci-artifacts.md).

**Review outcomes live in the entity-owned `review.ts` when its typed contract exists; no permanent per-locale Markdown review reports.** For Lessons, `ai.locales` is one verified PR reference for the completed AI-language review (the existing Lesson PR in the new entity-owned flow); `human.locales` retains per-language verified human-review PR references where actually applicable. These fields do **not** require creating additional reviewer PRs. Place review-specific linguistic decisions in short `//` comments above the relevant PR-valued entry. If `review.ts` or stable assembled Props are unavailable, preserve exact evidence in the same entity PR (and a historical Issue only if one exists); do not fabricate approval. Reviewer work is read-only by default; the authorized entity coordinator records verified values.

**Never edit generated Markdown to change translations.** The one-day Actions ZIP is a disposable preview of canonical Code. There is no repository reference directory, new report cleanup commit or automatic cleanup at Ready; only canonical source and review evidence belong in Git.

## Lesson translation review references

Canonical implemented Lessons are discovered under `content/<textbook>/data/lessons/<last-uuid-hex-digit>/<lesson-uuid>/*.data.ts`. The same on-demand command includes `lessons/<textbook>/<bucket>/<lesson-uuid>/<language>.md` in the ZIP. Each document includes Lesson Sections, the complete Question Bank, Flashcard Bank and descriptive metadata for non-text media, without embedding media. Reviewers should select the assigned Lesson and language, verify `manifest.json` for missing documents/failures, compare the source meaning, and make changes only to canonical authored code. Do not edit temporary Markdown.

**Implemented Lesson reference:** [generate-lessons-markdown.mjs](../../../shared/engine/scripts/generateLessonsMarkdown/generate-lessons-markdown.mjs) is dispatched through [Generate Translation Review Artifacts](../../../scripts/generateTranslationReviewArtifacts/README.md). Use the actual scoped command, verify the exact source SHA in `manifest.json`, and do not rely on the removed root `scripts/generate-lessons-markdown.mjs` path or the historical Agent 4 prerequisite.

## Owner-directed independent review

For Course, Lesson, Questions and Flashcards, the owner assigns a **different reviewer agent/context** to the **existing entity PR**, pins its source SHA and locale scope, and expressly authorizes any localized fixes **in that same PR**. No separate translator/reviewer PR or integration merge is part of this new entity review process. Review the full assigned Markdown, not only the diff; unsupported or incomplete source-derived documents remain a scoped hard stop. Ready and entity PR merge are separate owner decisions after real checks. For non-entity campaigns, follow the owner's existing integration/subtask permissions in [Manage Translation Production](./manage-translation-production.skill.md). Historical campaigns retain their recorded ownership and merge boundaries; no report ZIP or generated Markdown is committed to source.

**Source clarification:** The old example Lesson path `data/lessons/<group>/<slug>/` is historical. New code uses UUID-addressed `data/lessons/<bucket>/<uuid>/`; always derive paths from current repo and inspect the manifest rather than following stale examples.
