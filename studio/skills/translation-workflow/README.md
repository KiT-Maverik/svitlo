# Translation Workflow

**Course/Lesson/Questions/Flashcards translation coordination:** For new work the **existing entity-owned PR** owns its frozen entity × locale scope, translator/reviewer assignments, source/review SHAs and status. Do **not** create separate translation integration, translator, reviewer PRs or branches, or a Translation Production Issue. An independent reviewer uses another chat/persona on the same branch at a pinned source SHA. Preserve historical Issues/PR evidence through [legacy recovery](./legacy-production-issues.md); do not force-migrate active campaigns. The owner chooses reviewer, source and permission for corrections.

**Persona:** [Technical Translator](../../personas/technical-translator.persona.md), for linguistic judgment across supported languages.

- **[Manage Translation Production](./manage-translation-production.skill.md):** plan nonoverlapping assignments **inside the existing entity PR**, with independent review at the owner-authorized source SHA. Missing scoped reference Markdown is a review stop, not a reason to delay unrelated batches.
- **[Review Translation](./review-translation.skill.md):** inspect complete Code-derived Markdown for only the requested entity family, textbook and locale, generated on the **entity PR**; verify manifest/source revision and clean artifacts there before merge.
- **[Technical Translation](./technical-translation.skill.md):** implementation of actual localized text changes in canonical `*.data.ts` / `*.locale.ts` files; mandatory TypeScript and source validation.
- **Standalone static-document translation:** not yet a published skill; propose it separately if needed. The active Technical Translation workflow covers typed localized source, not unapproved general document translation.

Reusable agent CI workflow: [Agent CI Artifacts](../../../.github/workflows/agent-ci-artifacts.yml). In a PR conversation, a `/agent-artifacts generate` posted by a user with **`write`, `maintain`, or `admin` repository access** triggers generation for that PR's head branch; when the agent is finished, `/agent-artifacts cleanup` removes its tracked artifacts. The workflow must exist in **main** before slash commands become active. A [dedicated merge guard](../../../.github/workflows/agent-ci-artifacts-guard.yml) blocks temporary files from entering `main` or `new-lesson` after the relevant workflow is active on the target branch. See [Agent CI Artifacts architecture](../../docs/architecture/agent-ci-artifacts.md).

**Review outcomes live in the entity-owned `review.ts` when its typed contract exists; no permanent per-locale Markdown review reports.** For Lessons, `ai.locales` stores the verified **entity PR number** only after all intended AI-language review has genuinely completed, while `human.locales` can store the **same entity PR number per independently human-reviewed locale** when supported by the actual contract. The PR body records the distinct reviewer identities, source SHAs and findings; numeric references alone are not sign-off. Review-specific linguistic decisions are short `//` comments beside the relevant PR-valued entry. If `review.ts` is not yet available or assembled Props cannot be hashed, preserve the source-specific evidence in the current PR (and any historical Issue when one actually exists) for later reconciliation; do not fabricate an approval. The review agent remains read-only by default; the authorized coordinator records verified values.

**Never edit generated Markdown to change translations.** It is a disposable view of canonical code. Do not add `.agent-ci-artifacts/` to `.gitignore`: the reviewer must access its temporary documents in the PR branch, and cleanup must remove them before merge.

## Lesson translation review references

Canonical implemented Lessons are discovered under `content/<textbook>/data/lessons/<last-uuid-hex-digit>/<lesson-uuid>/*.data.ts`. The same on-demand command builds `.agent-ci-artifacts/lessons/<textbook>/<bucket>/<lesson-uuid>/<language>.md`. Each document includes Lesson Sections, the complete Question Bank, Flashcard Bank and descriptive metadata for non-text media, without embedding media. Reviewers should select the assigned Lesson and language, verify `manifest.json` for missing documents/failures, compare the source meaning, and make changes only to canonical authored code. Do not edit temporary Markdown.

**Implemented Lesson reference:** [generate-lessons-markdown.mjs](../../../shared/engine/scripts/generateLessonsMarkdown/generate-lessons-markdown.mjs) is dispatched through [Generate Translation Review Artifacts](../../../scripts/generateTranslationReviewArtifacts/README.md). Use the actual scoped command, verify the exact source SHA in `manifest.json`, and do not rely on the removed root `scripts/generate-lessons-markdown.mjs` path or the historical Agent 4 prerequisite.

## Independent review in the entity PR

For new Course/Lesson/Questions/Flashcards localizations, the owner authorizes a distinct qualified reviewer and specifies the **existing entity PR, exact source SHA and entity × locale scope**. The reviewer works in a **different chat/context and persona**, but uses **the same PR branch** and its scoped Code-derived Markdown/manifest. Review the entire assigned content, not merely the diff, and fail closed for unsupported, missing or stale reference documents. A reviewer may apply owner-authorized localized corrections in the same entity PR; regenerate source-pinned references and re-review affected fields after fixes. A new reviewer PR, translation integration PR or branch is not required. Cleanup and final approval remain in this same entity PR, subject to real CI/production gates.

**Source clarification:** The old example Lesson path `data/lessons/<group>/<slug>/` is historical. New code uses UUID-addressed `data/lessons/<bucket>/<uuid>/`; always derive paths from current repo and inspect the manifest rather than following stale examples.
