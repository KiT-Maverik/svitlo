# Trusted direct Episode Stage 5

An Episode remains an independent, Course-owned narrative entity. Course Stage 5 allocates its UUID, exact Course parent placement, order and initial `draft.ts` handoff. Episode Stages 1–2 complete the same source with Scenario and supported ordinary Sections/Blocks. Stages 3–4 provide SHA-pinned content and experience review. The final **reviewed** draft invokes `materializeEpisodeStage5(input)` once through `@svitlo/engine/build`.

The authorized `/episode materialize` comment (or default-branch workflow dispatch with Episode/Course PR numbers) requires a real Draft child PR, its exact pinned source blob, unique owning Course PR, unchanged reserved Episode slot and parent Course ancestry. Stage 3/4 reviews stay mandatory editorial responsibilities, not machine-parsed eligibility. No automatic parent merge or parallel sibling composition edits are allowed.

The tokenless analyzer builds the ordinary trusted Engine, then runs the final imported TS entrypoint in the shared **read-only, no-network, non-root** worker. The Engine's `episodeWorkflowStage2_Schema` validates the authored object; the exact real Section/ContentBlock source materializers render its supported content. The trusted analyzer checks the immutable original Course handoff and separately invokes `restoreEpisodePlacement` to modify only the reserved parent slot. No final-draft literal AST decoder, partial renderer bundle, repeated compiler/virtual-source analysis or candidate execution in the write-token job.

The Episode renderer consolidates reviewed ordinary Section production notes into the Episode narrative specification before acknowledging Section handoff. Each reviewed Scene generates a blocked six-file component/test/CSS draft under the owning textbook's UUID-scoped Scene directory, without automatic registration or a duplicate Scene specification sidecar. The publisher independently allowlists the Episode and Scene path domains, enforces a complete six-file set for each Scene UUID and create-only no-clobber against the exact pinned Git tree. It verifies complete sealed file hashes, the original parent blob, handoff identity/order and **byte-exact parent restoration** before one non-force Git commit creating Episode modules and Scene drafts, replacing only the authorized parent source map/order, and deleting the original Episode draft. All uncompleted media and human QA blockers remain. Materialization does **not** produce physical assets, translations, a general event system, Quest runtime, Course merge, runtime Props or Stage 9/10 human approval.

**Validation:** `npm run package:build --workspace @svitlo/engine`, `npm run code:check:types --workspace @svitlo/engine`, `node --test scripts/ci/episodeMaterialization/episode-direct.spec.mjs` and `node --test shared/engine/generators/materializers/episode/materialize.spec.mjs`. Confirm an actual authorized default-branch job and committed revision before recording Stage 5 complete.
