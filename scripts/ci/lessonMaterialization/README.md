# Trusted Lesson Stage 6.1 materialization

**Migration target in PR #857; not proof of deployment.** Follow [source architecture](../../../studio/docs/architecture/typed-production-materialization.md) and inspect the actual current runner and tests.

An optional Course Stage 5 `CourseWorkflowLessonSeed` or standalone brief advances through the same UUID-addressed `draft.ts` to `LessonWorkflowStage1`, then full `LessonWorkflowStage2`. Stages 3–5 review/correct the Stage 2 source; no extra authoring contract or authored materializer call is required. The final `draft.ts` is one inert default-exported object with type-only imports and `satisfies LessonWorkflowStage2`. It is not a Configurator. Separately authorized `/lesson materialize` runs the trusted static Reader, canonical final Zod validation and concrete Lesson source generator. No Jiti/load/worker execution of authored TS is part of the target.

The gate requires one canonical changed source in a same-repo Draft Lesson PR, exact HEAD/blob and actor write access; it **does not** parse Course ancestry, PR editorial checklists or review verdicts. Trust the pinned source bytes, not the author's comments or a green Draft status. The read-only analyzer generates a bounded, nonpublishable source plan, seals output paths and SHA256 bytes. The privileged publisher reauthorizes and checks no-clobber, symlink ancestors and exact sealed files, then creates Lesson `index.ts`, owned Sections/Blocks, derived methodology and UUID-addressed six-file Scene drafts (with embedded removable specifications) while deleting `draft.ts` in exactly one non-force commit. Neither step executes candidate authored modules; the publisher never regenerates or reformats.

**Boundaries:** Stage 6.1 is not Stage 6.2 physical-resource completion, Stage 6.3 implemented/registered Scenes, Lesson Stage 7/8 independent Question/Flashcard banks or Stage 9/10 localization. Required Quiz/Flashcards Sections must be present/enabled; use safe nonpublishable stubs for genuinely incomplete selections, never fake bank IDs. No publication-ready Props or automatic human approval results from a successful source commit. Keep TODO blockers and historical YAML evidence.

**Validation after implementation:** Engine build/typecheck, Lesson Stage 6 source/transaction tests, static-reader valid/invalid Stage 2 fixtures, Scene create-only tests and a verified authorized Actions run. The old isolated-worker tests describe the pre-migration runner; retire or replace only with equivalent security assertions.
