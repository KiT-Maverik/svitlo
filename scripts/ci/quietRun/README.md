# Quiet CI command execution

Use `node scripts/ci/quietRun/quiet-run.mjs -- <command> [args...]` for human-readable test, lint, typecheck, build and dependency-install commands. On success it prints a compact `PASS` line and elapsed time; on failure it preserves the exit status and shows a bounded excerpt (including early recognized error lines). `SVITLO_CI_VERBOSE=1` is an **explicit opt-in for a new invocation** that streams the command's output.

**Do not wrap commands whose stdout is a protocol or feeds another tool.** This includes generators emitting JSON or other machine-readable data, shell pipelines/redirections that consume stdout, GitHub workflow commands (`::set-output`-style commands, `::error`, `::warning`, notices and group/control messages), GitHub API calls, authentication/authorization and credential/token operations. Quiet mode deliberately suppresses ordinary successful stdout; it is unsafe when a caller or workflow relies on that output. Use the unwrapped command for any protocol-bearing step. The `GITHUB_OUTPUT`, `GITHUB_ENV` and `GITHUB_STEP_SUMMARY` files remain available to a wrapped process; that does **not** make its stdout a safe protocol channel.

The runner does **not** redact secrets. Avoid printing tokens or sensitive data, including in verbose mode or failures; redact diagnostics **before** sharing them with an agent. Do not upload complete successful logs or use quiet output to bypass any CI assertions, error annotations, source-pin checks or exit codes. Quiet mode preserves nonzero process exit codes and attempts to surface annotation/error lines, but use the raw command wherever workflow-command fidelity is required.

For noisy content builds wrap the entire `build-changed-content.mjs` CLI only when its own stdout is not being consumed as structured output; **never** quiet-wrap individual JSON-producing inputs. Preserve `GITHUB_OUTPUT` and per-package failures. A bounded early-diagnostic buffer retains the first recognized TypeScript/build errors even after a long tail.

For AI diagnosis, follow [Agent CI failure triage](../../../studio/rules/ci-workflow.md#agent-ci-failure-triage-low-token-default): current PR head and required checks → failing job → failing step/annotations → bounded relevant excerpt. Do not download successful job logs by default. A normal GitHub job rerun cannot set a new `SVITLO_CI_VERBOSE` value; use a supported manual diagnostic invocation or a controlled local reproduction when detailed output is necessary.

The runner's unit tests exercise successful noise suppression, failure first cause and exit code, verbose opt-in, Windows npm launch, signal termination, GitHub error/warning annotations and file-based `GITHUB_OUTPUT` preservation. Run `node --test scripts/ci/quietRun/quiet-run.spec.mjs` after changes; the presence of a test is not proof that it passed. For direct human-readable Node tests that need no wrapper, prefer the native `node --test --test-reporter=dot` reporting mode. It prints compact successes with full native failure details. Neither mode permits hiding a workflow-command protocol or test assertion failure.

On Windows the runner starts the installed `npm-cli.js` with `process.execPath`, avoiding a `.cmd` shell invocation and preserving argument boundaries. CLI entrypoint detection accepts Windows and POSIX path separators; failures to locate npm are fatal rather than silent passes. Both are covered by unit tests.
