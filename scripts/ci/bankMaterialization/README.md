# Direct Question/Flashcard Bank Stage 5

Question and Flashcard Banks are independent Lesson-owned educational resources. Their Stage 1–3 authored objects remain in `questions/draft.ts` or `flashcards/draft.ts`; reviewed Stage 3 TypeScript directly calls `materializeQuestionBank(input)` or `materializeFlashcardBank(input)` from `@svitlo/engine/build`. No second YAML/JSON input, static literal parser, source expression decoder, intermediate local Git writer or hand-replayed generated TypeScript is part of the active path.

Post exactly `/questions materialize` or `/flashcards materialize` as a top-level comment on the existing Draft Bank PR, or use default-branch `workflow_dispatch` with exact bank and PR number. Trusted resolve independently checks actor write access, owning Lesson identity, real Lesson parent ancestry, pinned source blobs (including the exact owning Lesson `constants.ts`) and no unauthorized source changes. Independent Stage 4 review and Questions-first editorial decisions remain responsibilities of the owning agents and PR; the materialization gate does not parse verdicts, checklists or PR prose.

The read-only analyzer builds the ordinary **trusted Engine**, then runs the approved direct call once inside the shared credential-free worker (network disabled, non-root, read-only mounts). Real Zod/Configurator contracts and entity materializers check bank source and generate modular files. For Questions, an absent untracked UUID media file or an absent optional media field may materialize as source-only placeholders with explicit `TODO (BLOCKER)`. For **both banks**, newly reviewed Scenes absent from the verified textbook are materialized using the shared six-file Scene draft templates; existing fully blocked six-file drafts are reused without overwrite **only if the embedded, inert TSX specification exactly matches the pinned Bank Stage 3 specification**. A differing or missing embedded specification fails closed; reviewed changes must be reconciled in the owning Scene by its implementer, never silently dropped. Partial/symlinked drafts and unreviewed specifications fail closed. A real tracked media file, executable Scene entrypoint, registry and optional legacy `specification.md` are verified against the exact pinned checkout. The bank's reviewed `production.specification` is pinned evidence when a Lesson/Episode Scene has no sidecar. None of those unresolved placeholders proves that publication can proceed: altered/tracked-but-missing files, symlinks, forged paths and malformed registry entries still fail closed. Flashcard evidence retains its stricter unresolved **media** boundary; a complete, blocked Scene draft is source-only and is never accepted as registered implementation evidence. A separate trusted read-only step verifies Lesson reference provenance and all authored Question/Card/Side inventory and registered Scene/media assets against real pinned files, not assertions made by the reviewed entrypoint. It independently checks that the Bank language plan agrees with the statically parsed Lesson constants, refuses incompatible restored-language states, regenerates and byte-compares all approved Scene drafts against the reviewed source, and seals `publishable:false` outputs and their SHA-256 hashes.

The write-token publisher **does not import candidate code or call the generator again**. It reauthorizes the current PR/source/head/branch, validates bounded file paths and bytes and makes exactly one non-force Git tree commit that consumes `draft.ts` and creates the bank's `index.ts` and resources. It never creates Bank-specific `questionsLanguages.ts`/`flashcardsLanguages.ts`, never changes the Lesson's `constants.ts`, Scene registry or Quiz/Flashcards Sections, nor approves translation, media, Props publication or Stage 7 completion. Newly reviewed Scene templates are limited to the exact textbook-scoped UUID directory and six-file allowlist; existing implementations are not overwritten.

**Validation:** `node --test scripts/ci/bankMaterialization/bank-typed-materialization.spec.mjs`, `npm run package:build --workspace @svitlo/engine`, `npm run code:check:types --workspace @svitlo/engine` and independent bank materializer tests. Verify an actual authorized Actions run and output commit after deployment to default `develop`.
