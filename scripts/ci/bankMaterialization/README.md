Their Stage 1–3 authored objects remain in `questions/draft.ts` or `flashcards/draft.ts`; reviewed Stage 3 TypeScript directly calls `materializeQuestionBank(input)` or `materializeFlashcardBank(input)` from `@svitlo/engine/build`. No second YAML/JSON input, static literal parser, source expression decoder, intermediate local Git writer or hand-replayed generated TypeScript is part of the active path.

Post exactly `/questions materialize` or `/flashcards materialize` as a top-level comment on the existing Draft Bank PR, or use default-branch `workflow_dispatch` with exact bank and PR number. Trusted resolve independently checks actor write access, owning Lesson identity, real parent/Question-first ancestry, no unauthorized source changes, and accepted independent Stage 4 review evidence pinned to the current SHA and draft blob. Questions N/A has a distinct authenticated Lesson-owner decision; it is not inferred from absent Quiz Sections.

The read-only analyzer builds the ordinary **trusted Engine**, then runs the approved direct call once inside the shared credential-free worker (network disabled, non-root, read-only mounts). Real Zod/Configurator contracts and entity materializers check bank source and generate modular files. A separate trusted read-only step verifies Lesson reference provenance, Question-first prerequisites, all authored Question/Card/Side inventory and registered Scene/media assets against real pinned files, not assertions made by the reviewed entrypoint. It seals `publishable:false` outputs and their SHA-256 hashes.

The write-token publisher **does not import candidate code or call the generator again**. It reauthorizes the current PR/review/head/branch, validates bounded file paths and bytes and makes exactly one non-force Git tree commit that consumes `draft.ts` and creates the bank's `index.ts` and resources. It never creates or changes Lesson Quiz/Flashcards Sections, nor approves translation, media, Props publication or Stage 7 completion.
