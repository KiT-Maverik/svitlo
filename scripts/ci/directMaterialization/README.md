# Shared declarative materialization boundary

**#857 migration target; inspect the actual default-branch implementation before use.** Trusted Code owns a single shared TypeScript Draft Reader and the immutable analyze/publish transaction. The **six** entity-specific authoring commands are `/course materialize`, `/lesson materialize`, `/episode materialize`, `/questions materialize`, `/flashcards materialize` and `/assessment materialize`. Their exact invocation and output paths remain in the five entity [runbooks](../courseMaterialization/README.md) (Course, Lesson, Episode, Banks, Assessment) and the [workflow inventory](../../../studio/docs/architecture/declarative-draft-workflow-inventory.md).

The author-edited `draft.ts` is an inert default-exported, type-only-imported, stage-checked literal. The tokenless analyzer reads the exact pinned Git blob as text and **parses, never transpiles, Jiti-imports or evaluates** it. The AST allowlist rejects arbitrary expressions, imports of runtime values, prototype keys, duplicate keys, unknown statements, excessive depth or size and extra exports. A canonical **final-stage** entity-specific Zod schema validates the parsed plain value; an intermediate handoff seed is not falsely promoted to final Stage. Only trusted concrete Engine materializers build normal executable `index.ts` Configurators. The static Reader itself never searches repositories, evaluates Lesson dependencies, checks PR readiness or makes pedagogical review decisions.

The Course-generated child preview has a distinct `<placement>/stub.ts` import/export verified by the shared `reserved-parent-slot.mjs` TypeScript AST reader without evaluation. The Course publisher checks every pending `stubSourcePath` against its sealed inventory and the immediate parent. Episode/Assessment publishers pin the stub and parent Git blobs and atomically consume the stub with the reviewed draft; Lesson integration is separately authorized.

The existing same-repository Draft PR writer permission, source commit/blob and relevant parent branch/slot/Question/Scene/media/locale ownership checks remain independent trusted gates. The tokenless analyzer seals source output bytes, bounded allowlisted paths, provenance and SHA256 with `publishable:false`. The write-token publisher independently reauthorizes actor, HEAD, immutable dependencies, hash match, safe paths and create-only no-clobber, and makes **one non-force Git commit**, deleting the consumed `draft.ts`. Episode and Assessment may update only the exact pinned one parent placeholder. It must **never** rerun a candidate draft, re-materialize or reformat sealed bytes.

Do not delete the pre-migration isolated worker or weaken its tests until Agent C proves the new reader/real-dependency trust boundary is integrated. Do not claim deployment from a Draft test or use an undeployed comment as an acceptance test. Explicit independent reviews, accessibility/media/language publication blockers, bank ownership and human QA remain unchanged.
