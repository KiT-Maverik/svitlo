# Trusted direct Course Stage 5

Stage 1–3 progressively author **one Course object** at `content/<book>/data/courses/<bucket>/<uuid>/draft.ts`. During Stage 4, after independent substantive review and correction, keep its `satisfies CourseWorkflowStage3` contract and make it the argument of **one** `materializeCourse(input)` invocation imported from `@svitlo/engine/build`. Pin that exact reviewed source blob and HEAD before authorizing Stage 5.

```ts
import { materializeCourse } from '@svitlo/engine/build';
materializeCourse(reviewedCourse satisfies CourseWorkflowStage3);
```

Reused existing Lessons are real imported Lesson Configurators supplied as `production.source` and their real `production.sourceExportName`. If `production.existing` is a built sparse `build.overrides()` result, supply the corresponding **original plain, JSON-safe** `production.sourcePatch`. The materializer must verify that the real Lesson Build API reproduces the reviewed built result. Never reconstruct the raw patch from Props, override an independently owned Lesson, fabricate import aliases or import an unmaterialized Lesson. Candidate and trusted default-branch Lesson trees and source revisions must match.

Independent Stage 4 review remains required by the editorial Course Flow but is not a machine-parsed eligibility gate.

The exact top-level `/course materialize` comment or default-branch `workflow_dispatch(pr_number)` is authorized only for the current same-repo Draft Course PR, write-capable actor and one canonical changed root draft. `resolve` pins HEAD and source blob without parsing editorial review records. `analyze` compiles the **ordinary** trusted Engine package and executes only the reviewed direct call in the credential-free, read-only, network-disabled shared worker. It validates Course Zod/Configurator contracts, output inventory, immutable reused Lesson dependencies and bounded output paths/hashes. The publisher rejects missing, unregistered or mismatched Course Lesson seeds, Episode handoffs and Assessment draft stubs/seeds, including upstream Lesson placement dependencies and conflicting identity, order and canonical ownership. No untrusted code runs in the publisher; no AST decoder, special trusted-Lesson esbuild bundle, second semantic validator or privileged replay exists in the active execution path. Course-generated Lesson/Episode handoffs retain their JSON literals via a narrow `// prettier-ignore` marker; other emitted source is styled later by the existing Ready-PR autoformatter.

The analyzer seals a complete `publishable:false` manifest. `publish` reauthorizes the actor, HEAD, source and immutable dependencies, verifies every output byte, prohibits existing targets/symlinks/path escapes, and atomically deletes `draft.ts` and creates `index.ts`/Course-owned files using one non-force Git Data API commit. The original bytes remain in Git history. A separate metadata-only task confirms the committed tree and reconciles Course Lesson, Episode and Assessment inventory tables. It preserves the human-maintained ten-stage Course PR checklist and stage-review evidence; the Assessment inventory is only the canonical ordered placement handoff, not a second editorial tracker.

Stage 5 may allocate new Lesson seeds, Episode handoffs and pending Course/Module/Chapter **Assessment slots**, but **does not** complete them, start child PRs, create Questions/Quiz, implement banks/Scenes, translate, publish Props or grant QA acceptance. Assessment Stage 2 placement alone determines whether Course Stage 7 Design Assessments applies; with zero Assessment slots in the entire verified hierarchy, that Course stage is explicitly Skipped. Each pending Lesson, Episode and Assessment slot retains its reviewed `content.order` position as a blocked `defineLessonStub`, `defineEpisodeStub` or `defineAssessmentStub` Configurator in the immediate owning `index.ts`. The separate typed draft is not silently completed. Reused Lessons are imported directly into that parent, optionally with a validated `placeLesson` Config patch at that exact placement; no wrapper/re-export directory or Course-root override export is emitted. The `placementSourcePath` inventory field points to this parent, while `sourcePath` points to the immutable reused Lesson or pending draft. The single Course-root `constants.ts` owns active and planned language context; child parent indexes import its `languages`/`Languages` and cannot produce local language tuples. These are source-layout contracts, not completed Assessment Props. Pending work is represented by typed child stubs in `content.items/order` and verified pending inventories; child draft seeds retain actionable `TODO (BLOCKER)` markers. Parent indices do not duplicate pending-child TODOs that become stale after one-slot restoration. The Course root retains its **independent** release-review/QA gate and `constants.ts` retains any outstanding locale blocker.

**Validation:** `npm run package:build --workspace @svitlo/engine`, `npm run code:check:types --workspace @svitlo/engine`, `node --test scripts/ci/courseMaterialization/typed-course-direct.spec.mjs`, and the existing concrete Course materializer/metadata tests. A test pass does not prove actual deployment; verify a real authorized default-branch workflow run, reviewed input SHA, output commit and updated inventory.
