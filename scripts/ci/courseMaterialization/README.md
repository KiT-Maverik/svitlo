# Trusted Course Stage 5 materialization

**Migration status:** Declarative authoring is the #857 integration target, not automatically the deployed default-branch behavior. Read [canonical source/trust architecture](../../../studio/docs/architecture/typed-production-materialization.md) and current `resolve/analyze/publish` code before invoking.

Stages 1–3 author one Course `draft.ts`, Stage 4 independently corrects and reviews the **same inert default-exported literal** satisfying `CourseWorkflowStage3`. No author-written `materializeCourse(...)` call, runtime Lesson import, computed expression or `build.overrides()` execution belongs in that file. The owner separately authorizes the exact `/course materialize` top-level Draft PR comment (or the supported default-branch manual dispatch). The trusted shared Draft Reader parses the exact pinned source without executing it; the canonical Course Stage 3 Zod schema validates the plain value; the **trusted** Course source materializer then constructs nonpublishable source.

**Existing Lesson placement:** author `production.existing.id`, matching evidence and an optional plain `sourcePatch`; type-check the patch inline using `satisfies Parameters<typeof importedLesson.build.overrides>[0]` with an actual **type-only** Lesson import. No live `production.source`, built `base/locale` duplicate, derived override Props or new Lesson lookup in the reader. A separate trusted dependency gate must establish that the actual existing Lesson Configurator is safe to execute. Only trusted Engine source calls its real `build.overrides()` with that raw patch. Retain repeated placement-local overrides and exact UUID/locale/ordered child semantics. Nested override typing examples remain conditional on Agent B's tested generic support.

**Technical gate:** Resolve a same-repository Draft Course PR, current HEAD, uniquely owned canonical draft and authorized actor; pin byte-exact Git source and reviewed Lesson dependency identities. Editorial Stage 4 evidence is mandatory in the Course PR but is **not machine-parsed eligibility**. The read-only analyzer statically parses and validates pinned source, applies the trusted entity materializer, verifies bounded deterministic output and seals SHA256 bytes with `publishable:false`. The write-token publisher rechecks HEAD, actor, immutable dependencies, safe paths, symlinks and no-clobber, then commits the generated Course tree and deletion of draft in exactly one non-force Git commit, without re-materializing or formatting. A separate metadata-only step reconciles owned Lesson/Episode/Assessment inventories and the Course PR tables without altering human Stage tracking.

**Colocated preview ownership:** Every pending new Lesson, Episode or Assessment has one generated `<placement>/stub.ts` exporting a blocked `define*Stub({id,slug})`, imported solely by its immediate Course/Module/Chapter. The independent inert Lesson UUID draft or Episode/Assessment colocated `draft.ts` is never imported into that parent. Sealed manifests bind `stubSourcePath` to exact pending inventory and verify both the typed stub AST and the ordered parent import/slot. The publisher refuses unregistered, duplicate or foreign stubs. Subsequent Episode/Assessment/Lesson source materialization consumes only the reviewed child `draft.ts`; it never edits this parent or removes its `stub.ts`. Every pending stub import has its own immediately preceding actionable `TODO (BLOCKER):`. A Coding Agent may later replace the parent import with the real Configurator and delete the owned stub only after verifying actual implementation, TypeScript/preview compatibility and resources/locales. Missing Scenes, banks or translations do not authorize activation.

**Handoffs:** Stage 5 may allocate new Lesson `CourseWorkflowLessonSeed` drafts, Episode handoffs and ordered Course/Module/Chapter Assessment `AssessmentWorkflowSeed` drafts. These are single inert progressively typed objects, _not_ completed Stage 1/2 entities; all retain their parent `items/order`, blocked placeholder Configurator, source provenance and `TODO (BLOCKER):` where needed. Reused Lessons are imported in **generated** parent Configurator `index.ts` source, not in authored Course `draft.ts`; do not create duplicate Lesson wrappers or mutate standalone Lessons. Course root `constants.ts` owns its language tuple; no fabricated translations, assets, bank IDs, Scene implementations, Props or QA. Conditional Course Stage 7 depends on actual ordered Assessment slots; Stage 10 is mandatory human QA.

**Validation when the #857 code is integrated:** Engine package build/typecheck, Course Stage 5/unit and transaction tests, shared static-reader malicious-input tests, original seed/parent handoff tests and at least one authorized pinned default-branch Actions run. Do not claim these checks passed without executing them; the historical `typed-course-direct.spec.mjs` suite tests the old executable mode until migrated.
